## 1. 目标

让 `ManualBoundary`（P7.8）与 `AuthorizationMatrix`（P13.1）从**孤立组件**接入**真实生产调用点**，服务端在唯一 Run 创建入口执行：
1. **人工触发边界**（ManualBoundary）：拒绝 System Principal / 自动来源创建 Run（审计 P0-5）。
2. **服务端授权**（AuthorizationMatrix）：按权威身份校验 capability，fail-closed（审计 P0-6）。

**边界**：身份来源用**验签 claims**（run-invocation EdDSA JWS），非前端；不接真实 query-api/MySQL 权威身份（属真实环境 Integration Gate）；不改既有验签链。

---

## 2. 接入点：`/internal/v1/run-invocations`（唯一 Run 创建入口）

`main.py:498` 的 `run_invocations` 是**唯一验签的 Run 创建入口**（service token + EdDSA JWS + nonce replay + tenant/cluster 匹配）。在此接入边界，覆盖所有通过该入口创建的 Run。

**身份来源**（验签后可信）：
```python
claims = verify_run_invocation_ingress(request)   # 已验签，权威
scope = build_invocation_scope(claims)
principal_type = claims.get("principal_type")      # "user" | "system"
principal_id   = claims.get("principal_id")        # user UUID
tenant_id      = claims.get("tenant_id")           # canonical UUID
cluster_id     = claims.get("cluster_scope")[0]    # canonical UUID
```

## 3. 接入 ManualBoundary（审计 P0-5）

```python
from manual_boundary import ManualBoundary

_manual_boundary = ManualBoundary()   # 模块级单例

# run_invocations 内，验签通过后、构建 scope 前：
_manual_boundary.require_user_explicit(
    source="user_explicit",                    # 该入口为显式 POST（用户触发），非 alert/event 自动
    principal_type=claims.get("principal_type", ""),
)
# → System Principal 或自动来源 → ManualTriggerDenied(403 MANUAL_TRIGGER_REQUIRED)
```

- `require_user_explicit`：`principal_type != "user"` → 拒绝（System Principal 不能创建 Run）；`source not in {"user_explicit"}` → 拒绝。
- 该入口由已认证用户经 query-api 转发显式 POST，`source="user_explicit"` 语义成立；`allow_auto_new_run()` 恒 False 天然保证后台不自动建 Run。

## 4. 接入 AuthorizationMatrix（审计 P0-6）

```python
from authorization_matrix import AuthorizationMatrix, AuthzError

_authz_matrix = AuthorizationMatrix()   # 模块级单例，服务端配置规则（§5）

# run_invocations 内，验签 + ManualBoundary 通过后：
try:
    _authz_matrix.authorize(
        principal=str(claims["principal_id"]),
        tenant_id=claims["tenant_id"],
        cluster_id=claims["cluster_scope"][0],
        capability="ai.investigate",     # Run 创建（发起调查）对应 ai.investigate（engineer/operator/admin 拥有）
        action="create",
        risk="R0",                       # Run 创建 = R0（仅建 Run，不执行动作）
    )
except AuthzError as e:
    raise HTTPException(status_code=403, detail=f"{e.error_code}: {e}")
```

- `authorize()` fail-closed：principal 角色无 `ai.investigate` capability → `CAPABILITY_DENIED`；无匹配规则 → `AUTHZ_DENIED`；risk/confirmation/approval 不满足 → 拒绝。
- **角色由服务端 `ROLE_CAPABILITIES` 判定**（`_role_of(principal)`），忽略前端 role（防 tamper，P13.2）。
- **capability 选择**（代码事实）：`ROLE_CAPABILITIES`（authorization_matrix.py:18-27）无 `run.create`，发起调查（Run）对应 `ai.investigate`（engineer/operator/admin 拥有；viewer 无）。
- 回应审计 P0-6：Authorization Matrix 首次获得**生产调用方**（不再孤立）。

## 5. 授权规则配置（服务端）

`AuthorizationMatrix` 规则由服务端启动时注册（不可由前端注入）。**注意代码事实**：`authorize()`（authorization_matrix.py:66-73）用 `r.principal == principal` **精确匹配**，不支持通配符 `admin-*`。规则 principal 必须与 `_role_of()` 前缀映射后的实际 principal 精确一致，或显式注册每 principal。

方案 A（精确匹配，当前实现可直接用）：
```python
# _role_of(principal) 按前缀映射角色：admin_/op_/eng_/其它→viewer
# 因此规则 principal 需与 claims 的 principal_id 精确匹配（或统一命名 admin_xxx）
_authz_matrix.add_rule(AuthzRule(
    principal="admin_ops_01", tenant_id="*", cluster_id="*",
    namespace="*", resource="*", capability="ai.investigate", action="create",
    risk_max="R0", require_confirmation=False, require_approval=False,
))
```

方案 B（建议，需扩展 authorize()）：
```python
# 扩展 AuthzRule 支持角色级匹配（role 字段，authorize 时先算 _role_of(principal) 再比对）
# 避免为每 principal 注册，也避免通配符匹配的误授权。
AuthzRule(role="engineer", tenant_id="*", cluster_id="*", capability="ai.investigate", ...)
```
- **默认 fail-closed**：未配置规则的 principal → `AUTHZ_DENIED`（不默认放行）。
- 规则来源：开发期内存注册；生产建议从 query-api/MySQL 权威角色 SoT 加载（真实环境 Integration Gate）。

## 6. 接入顺序与失败语义

```
run_invocations:
  1. verify_run_invocation_ingress(request)        # 已有：service token + EdDSA + nonce
  2. ManualBoundary.require_user_explicit(...)     # 新增：拒 System/自动 建 Run
  3. AuthorizationMatrix.authorize(... run.create) # 新增：服务端授权 fail-closed
  4. build_invocation_scope(claims)                 # 已有
  5. tenant/cluster body 匹配                       # 已有
  6. brain.stream_sync(...)                         # 已有
```
任一步失败 → 403，不进入 Run 创建。
