# R2-A1-PlanStep Planner DAG 重构方案（Y2 架构 · v0.3 修订）

**日期**：2026-08-21
**状态**：DESIGN（仅设计，未实施；Y2 架构方向已批准，8 项实施级阻断点已闭环）
**目标**：把 Planner 从平行 `planner.PlanStep`（字符串 `step_id`）消费方全切到权威 `contracts.InvestigationPlan`（`List[contracts.PlanStep]`，UUID `id`），消除平行 `PlanStep`，为 Phase 10 持久化/恢复/SSE 打基础。

> **架构**：`PlanStepDraft → contracts.InvestigationPlan（唯一权威 DAG）→ PlanStepRuntimeState（唯一运行状态源）`。
> **本轮修订（v0.3）**：闭环 8 项实施级阻断点（Step ID 公式、label_index 持久化、状态源唯一、RuntimeState 权威化、禁 assert、Intent 字段映射、follow-up 原子性、验收范围）。

---

## 1. 三层分离与状态源唯一

```text
Planner.propose_plan(run_id, plan_id, intent, drafts)
        │  ① 完整校验（重复 label / 悬空依赖 / 环 / 预算）
        ▼
PlanStepDraft                                    ← 入参层（纯 spec，非合同）
  label / tool_id / params / dependency_labels
        │  ② 统一建立 label → UUID 映射（一次性，防悬空）
        ▼
contracts.InvestigationPlan                      ← 唯一权威 DAG（定义态）
  List[contracts.PlanStep]（id: UUID, depends_on: List[UUID]）
        │
        ▼
PlanStepRuntimeState                             ← 唯一运行状态源（权威模型，由 PlannerState 持有）
  step_id: UUID / result_ref / started_at / finished_at / attempt / outcome / lifecycle
```

**状态源唯一原则（阻断点 3）**：
- `PlanStepRuntimeState` 是**唯一运行状态源**。
- `contracts.PlanStep.status` 是由 runtime state 计算出的**投影**（只读派生，非独立写入源）。
- 每次迁移**原子更新** runtime state + InvestigationPlan 快照（二者同步）。
- **禁止**两边独立写入。

---

## 2. Step ID 确定性公式（阻断点 1）

```text
id = UUIDv5(FROZEN_PLAN_STEP_NS, "v1\0" + run_id + "\0" + plan_id + "\0" + label)
```
- **含 `plan_id`**：同一 Run 内不同计划版本（重规划）的 `s1` 得到不同 UUID，动作变化不复用步骤身份。
- **含 `run_id`**：跨 Run 隔离。
- **含 `"v1\0"` 版本前缀**：为未来 id 派生规则演进预留。
- 同一持久化 Plan（同 run_id+plan_id）可幂等恢复出相同 `id`。

---

## 3. label_index 持久化（阻断点 2）

`label → UUID` 映射**必须随 Plan 持久化**，否则重启后旧调用方/UI 无法反查。

- 放入权威 `contracts.PlannerState`，新增字段：
  ```python
  class PlannerState(ContractModel):
      # ...既有字段...
      step_label_index: Dict[str, UUID] = Field(default_factory=dict)   # label → step_id(UUID)
  ```
- 或（若不想污染 PlannerState）新增权威 `InvestigationPlanMetadata`。
- **注意**：`step_label_index` 不是 PlanStep 身份（身份是 `PlanStep.id`），但必须随 Plan 保存。
- 兼容层（UUID→label）从 `step_label_index` 反查，标记 deprecated + 设删除 Gate。

## 4. PlanStepRuntimeState 权威化（阻断点 4）

在 `contracts.py` 定义**权威** `PlanStepRuntimeState`（非普通平行类），并由 `PlannerState` 持有：
```python
class PlanStepRuntimeState(ContractModel):
    step_id: UUID                                   # 对应 contracts.PlanStep.id
    result_ref: Optional[str] = None
    started_at: Optional[datetime] = None
    finished_at: Optional[datetime] = None
    attempt: int = Field(default=0, ge=0)           # attempt ≥ 0
    outcome: Optional[str] = None                   # success/failed/skipped（结果）
    lifecycle: str = "pending"                      # pending/running/completed（生命周期）

    @model_validator(mode="after")
    def validate_state(self) -> "PlanStepRuntimeState":
        # 不变量：完成前 outcome 必须为空；完成后 outcome 必填
        if self.lifecycle != "completed" and self.outcome is not None:
            raise ValueError("未完成步骤不得有 outcome")
        if self.lifecycle == "completed" and not self.outcome:
            raise ValueError("已完成步骤必须记录 outcome")
        # 时间必须带时区
        for t in (self.started_at, self.finished_at):
            if t is not None and t.tzinfo is None:
                raise ValueError("时间必须带时区（非 naive）")
        return self
```
`PlannerState` 持有：
```python
step_runtime: Dict[UUID, PlanStepRuntimeState] = Field(default_factory=dict)
```

> **阻断点 6 修正**：`lifecycle`（completed=生命周期结束）与 `outcome`（success/failed/skipped=结果）是两个独立维度，权威 validator 强制"未完成无 outcome / 完成必有 outcome"，杜绝混叠。

## 5. 校验必须显式抛稳定错误（阻断点 5）

**禁止 `assert`**（优化模式下可能被移除）。显式抛出稳定错误码：
```python
class PlanStepValidationError(ValueError):
    def __init__(self, code: str, message: str):
        self.error_code = code
        super().__init__(message)

# 重复 label
raise PlanStepValidationError("DUPLICATE_STEP_LABEL", f"重复 label: {label}")
# 悬空依赖
raise PlanStepValidationError("DANGLING_STEP_DEPENDENCY", f"悬空依赖: {missing}")
# 环
raise PlanStepValidationError("PLAN_CYCLE_DETECTED", f"DAG 环: {node} -> {nxt}")
```

## 6. Intent 字段映射（阻断点 6）

当前平行 `Intent` 没有 `goal`/`target`。构造权威 `InvestigationPlan` 时显式映射：
```python
plan = contracts.InvestigationPlan(
    plan_id=plan_id,
    run_id=run_id,
    goal=intent.intent,                     # goal ← intent.intent（调查目标）
    target={
        "resource": getattr(intent, "target_resource_id", ""),
        "cluster": getattr(intent, "primary_cluster_id", ""),
        "type": getattr(intent, "target_type", ""),
    },                                      # target ← target_resource_id/primary_cluster_id/target_type
    steps=[...],
)
# agent ← ToolRegistry 权威映射（禁止默认猜测）
agent = _registry.get(d.tool_id).agent_type if hasattr(_registry.get(d.tool_id), "agent_type") else _AGENT_BY_CAPABILITY[d.tool_id]
```

## 7. follow-up 原子性（阻断点 7）

follow-up **不得原地 append**。必须：
1. 复用原 `plan_id`（同 Run + 同 Plan）。
2. 校验 label 唯一（新 label 不冲突）。
3. 校验依赖存在（依赖 label ∈ 既有 label_index ∪ 新 label）。
4. **重跑环检测**（含新依赖边）。
5. **原子重建** `InvestigationPlan`（追加新 `contracts.PlanStep`）+ `step_label_index`（新增 label→UUID）+ `step_runtime`（新增 runtime state）。
6. 一次事务完成，失败回滚全部。

## 9. Planner 方法改写点

| 方法 | 现状 | Y2 后 |
|---|---|---|
| `propose_plan(intent, steps)` | 平行 PlanStep | `propose_plan(run_id, plan_id, intent, drafts)`：校验 → label_index → 权威 InvestigationPlan + RuntimeState |
| `ready_steps()` | 字符串集合 | UUID 列表（`PlanStep.id`） |
| `complete_step(plan_id, step_id, result_ref)` | 字符串查找 | `step_id`=UUID；原子更新 `step_runtime`（lifecycle/outcome/result_ref）+ Plan 快照 |
| `add_followup_step(...)` | 原地 append | 原子重建（§7） |
| `_validate_dag(steps)` | 字符串环检测 | 移到 Draft 校验，抛稳定错误码 |
| `budget` | 平行 Budget | **拆独立任务**（§10），本次不碰 max_tools/max_latency |

## 14. 验收标准

1. 平行 `planner.PlanStep` 消除；唯一 DAG = `contracts.InvestigationPlan`。
2. `id` 确定性 UUID（含 run_id+plan_id+label+v1）；依赖从 label_index 取值（防悬空）。
3. 重复 label/悬空依赖/环 → 稳定错误码（非 assert）。
4. `PlanStepRuntimeState`（权威模型，`PlannerState.step_runtime`）是唯一运行状态源；`PlanStep.status` 是投影。
5. `lifecycle` 与 `outcome` 分离，validator 强制不变量。
6. `step_label_index` 随 `PlannerState` 持久化。
7. follow-up 原子重建。
8. 预算重构独立任务。
9. FROZEN_PLAN_STEP_NS + 黄金向量编码前落盘。
10. 完整回归（test_p76/p96/p710/investigation_state/agent_runtime）+ ruff + Go 全绿。
