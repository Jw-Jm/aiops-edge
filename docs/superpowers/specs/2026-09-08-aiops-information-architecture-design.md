# AIOps 多集群云平台资源运维与全新 UI 设计方案

**日期：** 2026-09-09

**状态：** 书面规格已完成，待审阅

**适用范围：** `observability-frontend`、`ai-apm-query-go` 及现有资源、图谱、调查、处置兼容接口

**设计方式：** 依据本次确认的产品目标从零设计页面结构、组件编排和视觉语言，不沿用现有页面布局作为设计基线。

## 1. 产品定义

本产品是面向**单一生产环境、多个 Kubernetes 集群**的智能云平台运维平台。平台首先回答整个生产云平台是否健康、哪些实际集群需要关注；进入某个集群后，再围绕该集群中的资源载体完成观测、调查和受控处置。

平台直接运维的主语是：

- Kubernetes 工作负载与运行时资源。
- Kubernetes 流量入口和服务发现资源。
- Kubernetes 持久化资源。
- KubeVirt 虚拟机及其实例、迁移和依赖关系。
- 支撑上述资源运行的 Kubernetes 节点、物理机、网络和存储。

业务、应用、APM 服务和中间件不作为一级资源类别或一级导航。如果它们部署在容器或 KubeVirt 虚拟机上，平台仍通过 Deployment、Pod、Container、Kubernetes Service、VM/VMI 等真实载体进行运维；业务名称、应用名称、中间件类型只作为标签、元数据或局部筛选条件保留。

## 2. 已确认的产品边界

### 2.1 必须成立

- 平台只有生产环境，不提供 `prod / dev / staging / test` 环境选择。
- 平台总览聚合当前用户有权查看的全部纳管 Kubernetes 集群，不受当前集群选择影响。
- 顶栏直接选择真实 Kubernetes 集群，不出现“生产平台”“生产集群”等虚构层级。
- 选择集群后进入该集群的详细总览；资源、观测、调查和处置均在明确的集群上下文中工作。
- 容器资源与 KubeVirt 虚拟机是同一级运维对象，不把 KubeVirt 虚拟机归入传统虚拟化产品线。
- 物理机、虚拟机、网络和存储都严格归属于一个 Kubernetes 集群；它们不构成跨集群共享资源池。
- Namespace 是 Kubernetes 内部组织和筛选维度，不是全局 Scope。
- 不提供全局搜索。资源名称搜索只出现在当前集群的资源目录等局部页面。
- 健康状态基于服务端事实和明确规则，不展示虚构的 0–100 综合分数。
- 关键内容完整可读，同时任何视口、卡片、图表、表格和图谱不得越出设计边界。
- 所有高风险动作继续经过能力校验、预检、审批、执行、验证和审计。

### 2.2 暂不作为产品主线

- 业务、应用、APM Service、中间件的独立目录、独立健康页和独立图谱入口。
- 多环境、多云账号、跨集群共享基础设施或跨集群批量变更。
- 低于 1024px 的完整生产处置体验。
- 重写现有数据库、Run/Evidence/Action 事实模型或扩大 AI 自动执行权限。

### 2.3 保留兼容但默认隐藏

底层已有 `business`、`application`、`service`、`middleware` 等实体和关联不删除，接口仍可读取，历史 Run、报告和深链继续解析。新 UI 默认不把这些类型显示为一级资源、图谱中心节点或导航入口；需要显示业务语义时，将其投影为载体资源的只读标签，并明确数据来源。

`k8s_service` 与历史 `service` 必须严格区分：前者在 UI 中显示为“Kubernetes Service”，属于受关注的流量与服务发现载体；后者是业务/APM 语义实体，默认隐藏。

## 3. 核心用户心智与信息架构

产品采用三层递进结构：

```text
生产云平台健康（全部纳管集群）
        ↓ 选择一个实际集群
集群详细总览（该集群的资源与风险）
        ↓ 选择一种资源或一个对象
资源运维（观测 → 调查 → 处置 → 验证）
```

### 3.1 一级导航

1. **平台总览** `/overview`
2. **集群运维** `/clusters/:clusterId`
3. **调查** `/clusters/:clusterId/investigations`
4. **处置** `/clusters/:clusterId/actions`
5. **报告** `/clusters/:clusterId/reports`
6. **系统管理** `/admin`，仅管理员可见

没有集群上下文时，点击“集群运维、调查、处置、报告”先要求选择真实集群，不渲染伪造的“全部集群”操作页。平台级问题可在平台总览查看，但创建 Run 或 Action 前必须落到一个明确集群。

### 3.2 集群内工作区

- 集群概览 `/clusters/:clusterId`
- 资源 `/clusters/:clusterId/resources`
- 观测 `/clusters/:clusterId/observe`
- 关系 `/clusters/:clusterId/graph`

调查、处置和报告保留为一级闭环入口，同时始终显示当前集群。集群内导航不按 Grafana、VictoriaMetrics、VictoriaLogs、DeepFlow、HugeGraph 等采集或存储组件拆分。

### 3.3 路由与上下文

- `/overview` 始终调用平台聚合接口；任何已保存的活动集群都不能改变其统计范围。
- 顶栏或集群列表选择集群时，先提交 `/me/scope`，再回读 `/me` 确认，成功后导航到 `/clusters/:clusterId`。
- 直接打开集群深链时，先校验该集群是否在 `/me.available_clusters` 中；若活动 Scope 不一致，则同步并回读后再渲染。
- 集群切换失败时保留原页面和原集群，不显示目标集群的缓存数据。
- 资源选择通过路径或查询参数表达，例如 `/clusters/:clusterId/resources/:entityUid`；资源不是顶栏全局 Scope。
- 页面级时间范围提供最近 15 分钟、1 小时、6 小时、24 小时；创建 Run 时冻结为绝对起止时间。
- Run 打开后使用只读快照，不因顶栏选择变化而被改写。

## 4. 健康语义与数据真实性

### 4.1 统一状态

全站只使用四个顶级健康状态：

- **健康**：权威来源确认正常且数据在有效时间内。
- **降级**：仍可提供服务，但存在明确异常、能力下降或采集覆盖未达到服务端配置的要求。
- **严重**：存在服务端确认的不可用、关键故障或最高等级风险。
- **未知**：关键来源无数据、数据陈旧、权限不足或无法形成可信判断。

前端不计算综合分数，也不根据资源数量、告警数量或单一利用率自行创造平台健康。聚合接口返回 `status`、`status_reasons`、`generated_at`、`source_statuses` 和规则版本，UI 展示状态依据；缺失证据必须表现为“未知”，不能默认为绿色。

### 4.2 平台状态

平台状态由后端根据纳管集群状态、平台组件状态、采集覆盖和数据时效按已配置规则计算，并返回可解释原因。UI 只呈现，不在浏览器中重复实现规则。至少显示：

- 当前平台状态及一至三条主要依据。
- 纳管集群总数，以及健康、降级、严重、未知集群数。
- 采集覆盖率：已成功采集的预期目标数 / 纳管目标数，并显示分子、分母和统计时间。
- 最新数据时间和数据时效标签。
- 平台组件状态。
- 当前最高优先级风险及其所属集群、资源、持续时间和证据状态。

当部分集群不可读取时，总数、已读取数和未读取数必须分别展示；不得用已读取样本冒充全量。

### 4.3 集群状态

集群详细总览显示后端确认的集群状态与依据，包括 API 可达性、资源同步、采集覆盖、关键组件、异常资源和数据时效。节点数、Pod 数、VM 数等只作为资源事实，不直接等价于健康。

### 4.4 数据区域状态

所有卡片、图表、列表、图谱和抽屉都必须覆盖：

- 加载中。
- 无数据或无结果。
- 来源错误，可重试。
- 部分数据，明确已读取与缺失范围。
- 数据陈旧，显示快照时间。
- 无权限，不暴露被隐藏对象的名称或数量。

禁止用 `JSON.stringify` 直接堆叠主界面；原始 JSON 仅能出现在有大小限制、格式化和复制能力的折叠区。

## 5. 资源载体模型

### 5.1 一级展示分组

资源目录不再使用“计算、网络、存储、Kubernetes、应用服务”五域平铺。集群内以运行职责组织为两个同级主组和一个支撑组：

1. **容器资源**
   - 工作负载：`deployment`、`statefulset`、`daemonset`、`replicaset`、`job`、`cronjob`
   - 运行实例：`pod`、`container`
   - 流量与发现：`k8s_service`、`endpoint_slice`、`ingress`
   - 持久化：`pvc`，并关联 `pv`、`storage_class`
2. **KubeVirt 虚拟机**
   - 一级资源：`vm`、`vmi`
   - 生命周期证据：`migration`，不作为资源目录的一级对象
   - 关联磁盘、网络、Pod、Kubernetes 节点和物理宿主
3. **运行支撑**
   - Kubernetes 节点、物理服务器、网络、NAD、网卡、交换机、磁盘、PV、StorageClass
   - 作为资源目录的辅助分类和关系上下文呈现，不与容器/KubeVirt 抢占首屏主层级

`job`、`cronjob`、`ingress` 若现有 Graph DTO 尚未具备，需要扩展已知类型和只读资源目录；在数据源未接入前显示明确的“尚未采集”，不得模拟数量。

### 5.2 稳定引用

```ts
export type ResourceGroup = 'container' | 'kubevirt' | 'support'

export interface PlatformResourceRef {
  clusterId: string
  uid: string
  type: GraphEntityType
  group: ResourceGroup
  name: string
  namespace?: string
}

export interface ClusterContext {
  tenantId: string
  clusterId: string
  timeRange: TimeRange
}
```

约束：

- `clusterId` 是唯一授权根，`resource.clusterId` 必须与路由中的集群一致。
- UID 使用图谱 `entity_uid` 或后端稳定资产 UID，不使用显示名称拼接身份。
- Namespace 只用于 Kubernetes/KubeVirt 资源定位与当前页面筛选。
- 资源目录、详情、图谱、观测查询键都包含 `tenantId + clusterId + entityUid + timeRange` 中适用的字段。
- 集群切换时取消旧请求并清理旧资源缓存，避免跨集群残影。

### 5.3 业务语义投影

业务、应用、中间件和 APM 服务数据允许出现在资源详情的“业务标签”区域，例如：

```text
所属应用：订单中心（来源：resource label）
组件类型：Redis（来源：inventory annotation）
负责人：平台中间件组（来源：CMDB）
```

这些字段不改变资源身份，不独立生成健康结论，不参与顶栏 Scope，也不能掩盖真实载体名称。不存在可信映射时显示“未关联业务标签”，不通过名称猜测。

## 6. 完整显示与边界控制

“显示完整”不等于把所有数据一次铺满屏幕；“不超限”也不允许用不可恢复的省略隐藏关键内容。统一规则如下：

### 6.1 文本

- 页面标题、资源名称、状态原因、风险名称和错误说明必须完整可访问。
- 短文本优先自然换行；不可断开的 UID、镜像地址、标签值允许在自身容器内断词。
- 超过卡片合理高度的描述先展示结构化摘要，并提供明确的“展开全部”；展开后在原位或有宽高边界的详情面板中显示全文。
- Tooltip 只用于快速查看，不能成为访问完整内容的唯一方式。
- 技术 ID 允许视觉缩写，但旁边必须提供“查看完整值/复制”，复制值必须完整。

### 6.2 表格与列表

- 默认列只承载完成当前任务所需信息，完整字段进入详情，不把 15–20 列硬塞入首屏。
- 表头、主名称、状态和主动作不得被无提示截断。
- 页面本身禁止横向溢出；确需展示宽结构时，只允许在有明确边界的局部容器内滚动，并保留首列和操作列。
- 大列表使用服务端分页或虚拟滚动，显示匹配总数、当前范围和筛选条件。
- 筛选结果与导出结果必须说明范围，不能把当前页当成全部结果。

### 6.3 卡片与图表

- 卡片采用最小高度而非强制固定内容高度；同一行通过网格对齐，不靠裁掉内容维持齐平。
- 关键数字过长时缩小至设定下限后换行，不越出卡片；单位不与数值分离到不可理解的位置。
- 图表只绘制适合当前画布的数据密度，完整时间点通过缩放、时间选择、明细表或下载访问。
- 图表区域裁剪绘图元素，但 Tooltip、图例和轴标签必须保持在组件边界内。
- 所有弹层使用 `max-width`、`max-height` 和内部滚动；不得超出可视窗口或遮住关闭入口。

### 6.4 响应式重排

宽度不足时按“重排 → 收起辅助区 → 进入详情”的顺序适配，不通过整体缩放页面解决。任何支持视口下均不得出现页面级横向滚动、操作按钮重叠、浮层出界或完整内容无入口。

## 7. 全新 UI 壳层与视觉语言

### 7.1 页面框架

桌面端采用全新“导航轨 + 工作区顶栏 + 内容画布”结构：

```text
┌──────────┬──────────────────────────────────────────────────────────────────┐
│ 产品标识 │ [选择 Kubernetes 集群 ▾]             数据时间  通知  用户       │
├──────────┼──────────────────────────────────────────────────────────────────┤
│ 平台总览 │ 页面身份 / 状态依据 / 最后更新 / 最多两个主动作                 │
│ 集群运维 │                                                                  │
│ 调查     │                         内容画布                                 │
│ 处置     │                                                                  │
│ 报告     │                                                                  │
│ 管理     │                                                                  │
└──────────┴──────────────────────────────────────────────────────────────────┘
```

- 导航轨桌面宽 88px，以图标和短标签组成，不沿用宽侧栏菜单。
- 工作区顶栏高 64px，只保留集群选择、页面时间、通知和用户入口。
- 不设置第二条全局 Scope Bar，不提供全局搜索、环境、Namespace、节点或资源选择器。
- 集群选择器是唯一主要上下文控件，显示真实集群名称和状态，不塞入节点等次级选择。
- 平台总览标题旁固定显示“全部纳管集群”，明确不受最近集群影响。
- 页面级筛选和资源搜索放在内容画布内，与具体页面共同滚动。

### 7.2 视觉语言

- 背景 `#F3F5F7`，主表面 `#FFFFFF`，弱表面 `#F8FAFC`，边框 `#D9E0E7`。
- 主文本 `#162033`，次文本 `#5C687A`，交互蓝 `#2F5BD3`。
- 严重红 `#C83C35`、降级橙 `#C26A1B`、风险黄 `#A87708`、健康绿 `#168654`、未知灰 `#6B7482`。
- 健康状态始终同时使用文字、图标和颜色；资源类别颜色与健康颜色分离。
- 页面标题 22px，区域标题 16px，正文 13–14px，关键数字 24–28px。
- 卡片圆角 10px，边框优先于阴影；主间距 24px，区域间距 20px，卡片内间距 16px。
- 禁止大面积渐变、彩虹 KPI、装饰性光效、无意义动画和密集边框。

### 7.3 信息密度

- 首屏先给结论、证据和行动入口，再给资源数量与趋势。
- 同一行关键事实不超过 6 个；不同语义不强行做成等宽彩色 KPI 卡。
- 状态卡使用一致的标题和数值基线，允许内容区因完整文本自然增高。
- 表格主列固定为类型、名称、定位路径和健康；UUID、来源和扩展字段进入详情。
- 图表必须显示标题、单位、时间范围、图例和来源；零值、无数据和采集中必须可区分。
- 加载、空、错误、部分、陈旧和无权限状态使用与最终内容相近的稳定尺寸，避免页面跳动。

## 8. 页面布局设计

### 8.1 登录页

- 左侧为产品定位与三项真实能力：多集群健康、资源载体观测、调查与受控处置。
- 右侧为紧凑登录卡，不展示虚构实时告警、客户数量或健康数据。
- 背景使用克制的资源关系线稿或网格，不使用与平台无关的城市、地球或云朵插画。
- 登录失败在表单内就近提示，保留输入，支持键盘和密码可见性切换。

### 8.2 平台总览：生产云平台健康

路由 `/overview`，统计范围固定为全部有权纳管集群。

```text
┌ 生产云平台健康 ──────────────── 全部纳管集群 · 更新于 10:32 ┐
│ 平台状态与依据 │ 集群四态分布 │ 采集覆盖 118/120 │ 最新数据 │
├─────────────────────────────────────────────────────────────┤
│ 集群健康矩阵与排序（7栏）         │ 最高优先级风险（5栏）     │
├───────────────────────────────────┴─────────────────────────┤
│ 平台组件状态（7栏）               │ 数据覆盖与时效（5栏）     │
├─────────────────────────────────────────────────────────────┤
│ 最近平台级变化 / 需要关注的集群                              │
└─────────────────────────────────────────────────────────────┘
```

首屏显示：

- 平台状态、状态依据和规则版本入口。
- 纳管集群数及健康/降级/严重/未知分布。
- 采集覆盖率的分子、分母、缺口与更新时间。
- 最新数据时间。
- 最高优先级风险，显示所属集群、真实资源载体、严重度、持续时间和主动作。
- 集群健康列表按严重、降级、未知、健康排序；点击实际集群进入详细总览。

第二层显示平台组件状态，例如资源同步、指标采集、日志采集、链路采集、拓扑同步、调查 Worker 和处置控制器。组件名称来自服务端清单，无数据时不自动补齐绿色项目。

平台总览只允许只读聚合、进入集群和开始集群级调查，不提供跨集群批量处置。

### 8.3 集群详细总览

路由 `/clusters/:clusterId`。页面头显示真实集群名称、连接状态、版本、最后同步、采集覆盖和返回平台总览入口。

```text
┌ cluster-a  [降级] ───────────────── 最近1小时  进入调查 ┐
│ 状态依据 / 采集覆盖 / 最新数据 / 关键组件                │
├──────────────────────────────────────────────────────────┤
│ 当前最重要问题（7栏）            │ 资源状态摘要（5栏）      │
├──────────────────────────────────────────────────────────┤
│ 容器资源（6栏）                  │ KubeVirt 虚拟机（6栏）   │
├──────────────────────────────────────────────────────────┤
│ 运行支撑：Kubernetes 节点 / 物理机 / 网络 / 存储         │
├──────────────────────────────────────────────────────────┤
│ 近期变更、数据质量、主影响链                              │
└──────────────────────────────────────────────────────────┘
```

- “容器资源”和“KubeVirt 虚拟机”视觉权重、卡片尺寸和下钻能力相同。
- 容器资源按工作负载、Pod/Container、Kubernetes Service/Ingress、PVC 展示健康分布和异常数。
- KubeVirt 展示 VM、运行中 VMI、未就绪、迁移中/失败、磁盘和网络异常。
- 运行支撑使用紧凑依赖带展示 Kubernetes 节点、物理宿主、网络和存储健康；发生关键故障时提升到问题队列，而不是永远藏在底部。
- 不显示“应用服务健康”一级卡片；可在问题或资源行中显示只读业务标签。

### 8.4 资源目录

路由 `/clusters/:clusterId/resources`。默认显示异常优先的资源载体目录。

- 顶部使用三个等权工作组切换：容器资源、KubeVirt 虚拟机、运行支撑。
- 当前页面内提供资源名称搜索、资源类型、Namespace、健康、数据时效筛选。
- Namespace 筛选只在适用的 Kubernetes/KubeVirt 类型中出现。
- 桌面宽屏使用 280px 筛选栏 + 资源结果区；快速详情从右侧有边界地滑入，不覆盖导航与关闭入口。
- 结果显示类型图标、名称、Namespace/定位路径、健康、关键症状、最后观测和关联 Run。
- 同名对象必须靠类型和定位路径区分。
- URL 持久化筛选与分页，刷新后可恢复；无权限或不存在的资源不回退到第一条结果。

### 8.5 资源详情

路由 `/clusters/:clusterId/resources/:entityUid`，采用全新“资源身份带 + 证据工作区 + 关系侧区”结构。

```text
┌ 类型 / 名称 / 定位 / 健康 / 数据时效 / 来源 / 主动作 ┐
├───────────────────────────────────────────────────────┤
│ 状态依据 │ 关键指标 │ 近期事件 │ 最近变更             │
├──────────────────────────────────┬────────────────────┤
│ 概览 / 观测 / 事件变更 / 调查     │ 依赖 / 影响 / 能力   │
│          证据工作区               │    关系上下文侧区    │
└──────────────────────────────────┴────────────────────┘
```

- 标题区显示类型、真实名称、Namespace/定位、健康、数据时效和来源。
- 摘要区显示状态依据、关键指标、近期事件和近期变更。
- 内容切换为概览、观测、事件与变更、关系、关联调查。
- 关系上下文显示上游/下游依赖、影响范围、可用能力和进入调查/处置。
- 处置按钮只由服务端 capability 返回；没有能力时显示只读说明。

类型化字段：

- Deployment/StatefulSet/DaemonSet：期望/就绪副本、镜像、Pod、Service、PVC、变更版本。
- Pod/Container：Phase、Ready、重启、资源请求/限制、节点、镜像、日志/Trace 可用性。
- Kubernetes Service/Ingress：类型、选择器、Endpoint、入口、目标工作负载和流量健康。
- PVC：容量、访问模式、绑定 PV、StorageClass、挂载工作负载和容量风险。
- VM/VMI：运行状态、CPU/内存、Namespace、所在节点、启动器 Pod、磁盘、网络、迁移状态。
- Kubernetes 节点：角色、版本、Ready、污点、容量、承载 Pod/VM、物理宿主。
- 物理机/网络/存储：真实身份、所属集群、与 Kubernetes/KubeVirt 载体的依赖关系和已接入健康事实。

字段缺失时显示“未提供”并标注来源，不显示“未知 Node/Namespace”一类混淆占位。

### 8.6 观测工作区

路由 `/clusters/:clusterId/observe` 或资源详情的“观测”内容区。

- 顶部为问题、告警、指标、日志、Trace、事件、变更七种证据模式，不把数据源产品名作为主导航。
- 主区使用 8 栏证据画布，右侧 4 栏为异常时间线、数据质量和进入调查入口。
- 选中资源时，以可见筛选标签完整显示资源类型、名称、Namespace 和时间范围。
- 未选资源时明确写“当前集群”，不写“全部资源/全部环境”。
- 数据源错误、部分结果、陈旧结果分别展示，不能降级为健康或空数据。
- Grafana 等外部工具保留为专家入口，不成为默认体验。

### 8.7 调查工作区

调查列表和工作台始终在一个明确集群下。列表突出资源载体、症状、影响、阶段、负责人和证据状态，Run ID 为辅助字段。

新建调查继承 `cluster + optional resource + timeRange`，用户显式提交后才创建 Run。工作台采用顶部冻结范围带，下方 7/5 分栏：

- 左侧：Evidence 时间线、指标/日志/Trace/事件原始证据和主故障链。
- 右侧：资源身份、当前结论、候选假设、反证、缺失证据和建议动作。

图谱默认显示“主故障链”；证据不足时必须标记 `insufficient_evidence`，禁止确定性根因措辞。

### 8.8 处置工作区

- 顶部按待预检、待审批、执行中、待验证、已完成/失败展示状态管线和准确计数。
- 主区为动作队列；右侧详情面板完整显示目标资源、风险、命令摘要、审批、执行日志、验证和回滚条件。
- Kubernetes 节点、Workload、Pod、KubeVirt VM、网络和存储只展示服务端已声明的动作。
- 资源页只提供“建议动作/进入处置”，预检、风险、审批、执行、验证和回滚审计统一在处置中心完成。
- Action 携带资源 UID、资源版本、Run、集群、动作版本和幂等键；资源版本变化必须重新预检。
- 不提供跨集群“一键执行”。

### 8.9 报告工作区

报告以集群内资源事件为主语，采用时间轴 + 证据/动作摘要布局，包含真实载体身份、影响链、证据、根因、动作、恢复验证和容量趋势。历史业务/应用/中间件字段可作为兼容标签展示，但不得替代资源载体。

### 8.10 系统管理

系统管理使用独立的设置导航，聚焦纳管集群、采集器、图谱同步、能力策略、用户和审计。集群接入状态与业务健康分开表达，避免“已纳管”等同于“健康”。

## 9. 知识图谱全新设计

### 9.1 图谱主语

默认图谱只以资源载体和运行依赖为主语：

- 容器链：Workload → Pod → Container。
- 流量链：Ingress → Kubernetes Service → EndpointSlice → Pod。
- 存储链：Workload/Pod/VM → PVC → PV → StorageClass/底层存储。
- KubeVirt 链：VM → VMI → Launcher Pod → Kubernetes Node → Physical Server。
- 网络链：Pod/VM → Interface/NAD/Network → Node/Physical Network。

`business`、`application`、APM `service`、`middleware` 节点默认不渲染；兼容关系只在“显示业务标签”开关或历史 Run 中以弱化注释呈现。

### 9.2 三种布局

1. **集群拓扑**：分层布局。集群在顶部，容器资源与 KubeVirt 两条同级泳道位于中部，节点/物理机/网络/存储支撑层位于底部。
2. **资源关系**：以当前资源为中心的径向布局，一跳邻居按运行、流量、存储、宿主分区。
3. **主故障链**：从左到右的 DAG，异常源在左，受影响资源在右，只强调有证据支持的传播路径。

专家探索允许按类型、关系、Namespace 和深度扩展，但不改变默认视图的主语。

### 9.3 大规模图谱与聚合

真实集群中的节点和边必然可能超过 `80 / 200`。因此这两个数字只作为默认设备上的**首屏渲染预算**，不是资源总量、查询总量或聚合上限：

- 后端返回匹配总数、已加载数、游标和是否仍有更多数据，不静默截断。
- 首屏预算默认 80 个可见节点、200 条可见边，可按设备能力配置；总数据量不设为 80/200。
- 超出预算的同类资源折叠为聚合节点，例如“Pod 146”“PVC 38”，聚合节点同时显示总数、异常数、未知数和已加载数。
- 展开聚合节点按页加载，不一次把全部实体放入画布；搜索可直接定位未渲染实体并重构局部视图。
- 关系等价列表使用虚拟滚动和服务端分页，可读取完整结果，不受画布预算限制。
- 数据部分、权限过滤和首屏聚合必须使用不同提示，避免把“未显示”误解为“不存在”。

### 9.4 节点与边视觉

- 节点使用紧凑资源卡而非同质圆点：类型图标、最多两行预览名称、状态角标、可选数量徽标；选中后在侧区完整显示名称和属性。
- 容器与 KubeVirt 使用不同中性色系分类条；健康状态只用于边框、角标和文字。
- 选中节点使用蓝色外环；严重/降级/健康/未知同时使用图标和文字。
- 结构归属边用中性实线，运行/绑定边用有向实线，推测关系用虚线，已确认故障传播链才使用红橙强调。
- 低缩放级别隐藏边标签；悬停、选中或放大后显示，避免文字覆盖。
- 节点超过 50 或用户启用减少动态效果时关闭布局动画。

### 9.5 图谱工作区

图谱页面采用“模式/筛选工具条 + 有边界的画布 + 320px 检查器”结构，画布高度受视口控制，不推动整个页面无限增高。工具栏固定提供适应画布、缩放、回到中心、全屏、层级深度、类型、关系、Namespace 过滤和图例。

右侧检查器完整显示所选资源的身份、健康、邻居、影响、证据和可用动作；窄屏改为底部 Drawer。图谱下方提供完全等价的关系/故障链列表，支持键盘、屏幕阅读器、分页和导出当前筛选。图谱加载失败时资源详情与关系列表仍可使用。

## 10. 只读接口与事实边界

### 10.1 平台聚合

新增或收敛以下只读投影：

- `GET /api/v1/platform/health`：平台状态、状态依据、集群分布、覆盖率、最新数据、组件状态、最高优先级风险。
- `GET /api/v1/platform/clusters?status=&q=&limit=&cursor=`：当前用户有权查看的纳管集群健康列表。

平台接口忽略活动 cluster，不接受客户端 tenant 扩权，不支持任何写操作。响应统一携带 `generated_at`、`partial`、`stale`、`warning_codes`、已读取/预期范围和规则版本。

### 10.2 集群与资源

- `GET /api/v1/clusters/{clusterId}/overview`
- `GET /api/v1/resources/catalog?group=&type=&namespace=&q=&health=&limit=&cursor=`
- `GET /api/v1/resources/summary`
- `GET /api/v1/resources/detail?uid=<encoded entity_uid>`

资源接口继续受服务端确认的 tenant + cluster 约束。目录和详情复用图谱与资产事实，不在浏览器拼接多套数据并猜测资源身份。

### 10.3 事实来源

- Query API、资源同步、Graph DTO 是资源身份和关系的权威来源。
- Run、Evidence、Hypothesis、RCA、Action 和验证结果继续是调查处置事实。
- 前端不根据颜色、名称或几何位置推断健康、关系方向、可执行能力或业务映射。
- 兼容接口仍需 `environment` 时，边界适配器固定发送 `prod`；该字段不进入 UI、URL Scope 或用户偏好。

## 11. 响应式、可访问性与性能

### 11.1 响应式

- **≥1440px：** 导航轨 88px；12 栏内容网格；图谱检查器和详情侧区常驻。
- **1280–1439px：** 导航轨 72px；辅助信息折叠为可展开区；右侧检查器缩至 288px。
- **1024–1279px：** 导航只显示图标并提供可访问标签；筛选栏和检查器改为 Drawer；双栏内容按优先级重排为单栏。
- **<1024px：** 允许查看平台与集群健康，生产处置显示不支持提示，不承诺完整编辑体验。

三档强制视觉验收视口为 1440×900、1280×720、1024×768。

### 11.2 可访问性

- 顶栏集群选择、导航、筛选、列表、Tab、图谱工具栏和等价关系列表支持键盘操作。
- 状态变化使用 `aria-live="polite"`，关键失败使用 `role="alert"`。
- 状态色同时配文字、图标或线型，对比度满足 WCAG AA。
- 图谱容器提供准确 `aria-label`，列表提供完整等价语义。
- 支持 `prefers-reduced-motion`，焦点环不能被自定义样式移除。

### 11.3 性能

- 平台聚合、集群概览和资源详情使用独立 query key，禁止活动集群污染平台级缓存。
- 切换集群取消旧请求，清空不兼容资源选择和图实例。
- 局部资源搜索防抖 250ms，最少 2 个字符；筛选和分页由服务端执行。
- 图谱按需加载邻居，销毁页面时释放 G6 实例与事件监听。
- 大列表使用分页或虚拟滚动；大图使用聚合与渐进展开，不下载全量后再前端裁剪。

## 12. 迁移与兼容

实现按照新设计重建页面组件和布局，不以修改现有页面排版作为目标；现有代码只用于复用已验证的 API、授权、Run/Action 事实和必要基础组件。

可独立发布阶段：

1. 建立平台聚合与集群概览只读接口，保证 `/overview` 不受活动集群影响。
2. 建立全新壳层，移除全局搜索、环境/“生产平台”标签、全局 Namespace 和全局资源选择器。
3. 新建集群详细总览和基于路由的集群上下文。
4. 新建容器、KubeVirt、运行支撑三组资源目录，并扩展 Job/CronJob/Ingress 类型。
5. 按新布局重建资源详情、观测、调查、处置、报告和管理页。
6. 重建知识图谱布局、聚合、渐进加载和等价关系列表。
7. 统一全部数据状态，完成三档视口与内容完整性回归。
8. 保留旧深链和历史数据兼容至少两个小版本，再移除废弃 UI 代码。

旧路由映射：

- `/observability/service` → 当前集群容器资源页，并提示原业务/APM Service 视图已收敛为真实载体；存在可信映射时可直接筛选对应 Workload、Pod 或 Kubernetes Service，不把两类 `service` 自动等同。
- `/observability/vms` → 当前集群 KubeVirt 资源页。
- `/infra/k8s` → 当前集群容器资源页。
- `/hardware` → 当前集群运行支撑页的物理服务器筛选。
- `/capacity` → 当前集群资源页的容量视图。
- 历史 application/business/middleware 深链进入兼容只读详情，并提供“查看实际载体”入口。

## 13. 验收标准

### 13.1 产品与数据

- `/overview` 在切换或恢复任何活动集群后，仍显示全部授权纳管集群的相同聚合范围。
- 顶栏无全局搜索、环境、生产平台、生产集群、Namespace、节点或全局资源选择器。
- 选择真实集群后进入 `/clusters/:clusterId`，Scope 提交与回读失败不会串数据。
- 平台首屏完整显示平台状态、集群总数与四态分布、覆盖率分子/分母、最新数据、组件状态和最高优先级风险。
- 页面不出现 0–100 健康分数，不用前端推断冒充健康事实。
- 容器资源与 KubeVirt 在集群总览中同级；业务、应用、中间件和 APM Service 无一级入口。
- Kubernetes Service 正常保留，并与历史 APM `service` 类型清晰区分。
- 物理机、虚拟机、网络和存储均带明确 `clusterId`，跨集群请求由服务端拒绝。
- 所有资源详情、调查和动作都能回溯到 canonical resource UID 与集群。

### 13.2 内容完整与 UI 边界

- 页面标题、资源名称、健康依据、风险、错误信息和动作结果均有无需猜测的完整查看路径。
- 不以不可恢复的省略号、只存在于 Tooltip 的文本或静默截断隐藏关键内容。
- 1440×900、1280×720、1024×768 无页面级横向溢出、按钮重叠、浮层出界或关闭入口不可见。
- 正常、加载、空、错误、部分、陈旧、无权限状态都经过视觉验收。
- 登录、平台总览、集群总览、资源列表、资源详情、观测、调查、处置、报告、管理页按本文全新布局实现，不以现有页面布局通过验收。

### 13.3 图谱

- 图谱默认主语是资源载体；容器与 KubeVirt 同级可辨，支撑关系清晰，标签不大面积重叠。
- 资源量超过 80 个节点或 200 条边时，总数准确、聚合可见、分页可展开、列表可读取完整结果，不静默截断。
- 节点完整名称和属性可在检查器访问，画布节点本身不因强行塞入全文而越界。
- 图谱不可用时资源详情和关系列表仍可操作。

### 13.4 关键端到端旅程

1. 登录 → 查看全部纳管集群的平台健康 → 识别最高优先级风险 → 进入实际集群。
2. 集群总览 → 查看容器异常 → 定位 Deployment/Pod/Container → 查看证据 → 创建调查。
3. 集群总览 → 查看 KubeVirt 异常 → 定位 VM/VMI → 查看节点、网络、磁盘关系 → 创建调查。
4. Kubernetes Service/Ingress → Endpoint/Pod 关系 → 指标/日志/Trace → 主故障链。
5. Run 主故障链 → Action Proposal → 预检 → 审批 → 执行 → 验证回显。
6. 大规模集群图谱 → 查看聚合计数 → 展开一页 → 搜索未渲染资源 → 切换等价关系列表。
7. 切换集群失败或深链无权限 → 保留原上下文并给出明确错误，不泄漏其他集群资源。
8. 长名称、长状态原因、大数值、宽关系和大量结果 → 内容可完整访问且页面不越界。

## 14. 非目标

- 不把 Namespace、物理机或“节点”提升为全局选择层级。
- 不恢复独立的业务应用、应用服务或中间件产品域。
- 不把所有资源一次性塞入一张图、一张表或浏览器内存。
- 不用页面饱满度为理由伪造 Owner、健康、关系、容量、风险或观测数据。
- 不自动执行高风险动作，不用隐藏按钮代替服务端鉴权。
- 不在本轮改变历史 Run/Action 数据的底层兼容语义。
