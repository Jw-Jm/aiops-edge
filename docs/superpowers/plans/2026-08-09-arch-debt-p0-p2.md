### Task 2: P0-2 告警事件持久化改为增量 Upsert（消除全表 ReplaceAll）

**Files:**
- Modify: `ai-apm-query-go/internal/store/alerts.go`
- Modify: `ai-apm-query-go/internal/api/alerts.go`
- Test: `ai-apm-query-go/internal/store/alerts_test.go`

**Interfaces:**
- 现有：`AlertEventDAO.ReplaceAll(rows)`
- 新：`AlertEventDAO.Upsert(rows []store.AlertEvent) error` — 增量 upsert 全部行（不再 DELETE 不存在的）
- 新：`AlertEventDAO.DeleteBefore(cutoff time.Time) error` — 清理超出上限的旧事件（按 last_timestamp 删最旧）

- [ ] **Step 1: 写失败测试**（`store/alerts_test.go`）
  - `TestUpsertInsert`：Upsert 新行 → 表中有该行
  - `TestUpsertUpdate`：同 id Upsert 两次 → 更新而非重复
  - `TestUpsertKeepsOthers`：Upsert 后**不删除**未在 rows 里的其他行（区别于 ReplaceAll）
  - `TestDeleteBefore`：DeleteBefore 后早于 cutoff 的行被删，晚于保留
- [ ] **Step 2: 运行确认失败**（TDD 红）
- [ ] **Step 3: 实现**
  - `store/alerts.go` 新增 `Upsert`：`INSERT ... ON DUPLICATE KEY UPDATE`（全部字段）
  - 新增 `DeleteBefore(cutoff time.Time)`: `DELETE FROM alert_events WHERE last_timestamp < ?`
- [ ] **Step 4: 改造 `saveAlertEvents`（alerts.go:265）**
  - 把 `d.ReplaceAll(rows)` 改为 `d.Upsert(rows)`，并在 upsert 后：
  - 若 `len(alertEvents) > maxAlertEvents`（1000），计算 cutoff（取保留的最新 1000 条里的最旧 last_timestamp），调 `d.DeleteBefore(cutoff)` 清理 MySQL 旧事件
  - 内存态 `alertEvents` 仍按现有逻辑裁剪（`alertEvents[last-max:]`）
- [ ] **Step 5: 运行测试**：`cd ai-apm-query-go && go test ./internal/store/ ./internal/api/ -run 'AlertEvent|Upsert|DeleteBefore' -v` 全绿 + `go build ./...`
- [ ] **Step 6: Commit**（`feat(arch): 告警事件持久化改增量 Upsert，消除全表 ReplaceAll`）

> **说明**：CH 迁移为后续可扩展优化，非本债修复；当前消除全量重写已解决核心债且保持低内存。
