5. **回弹（关键）**：orbstack **自动重建 cni0 网桥**（删后秒回，路由重新指向 cni0）；节点仅 1 个 `cali*` veth，其余 pod veth 被 orbstack 接管进 cni0 并重命名为 `veth*`。
6. **egress 仍不拦**：felix 日志确认识别 `default-deny-egress-event-collector` + `default_action:"Deny"`，但 workload endpoint `operUp=false status="down"`（felix 期望 `cali*` veth，节点实际无匹配接口）→ 规则不应用到真实流量。负向验证 8.8.8.8:443 仍 `open`。
7. **副作用（必须止损）**：删 cni0 后 coredns 网络被破坏（`nc: bad address 'clickhouse'` DNS 全坏）+ event-collector CrashLoopBackOff（连 clickhouse 超时）。

### 根因（诚实，环境锁定）
- **orbstack 2.2.2 锁定内置 CNI**：持续重建 cni0 网桥、忽略 `/etc/cni/net.d/` 里的第三方 CNI 配置（calico 写了 `10-calico.conflist` 但 kubelet 仍用 orbstack 内置 flannel/cni0）、把 pod veth 接管进 cni0 并重命名。`orb` CLI 无禁用内置 CNI 的开关（`orb help` / `orb config` 无 cni/network/flannel 键）。
- 因此 calico 无法真正接管 veth 创建，felix endpoint 永远 down，NetworkPolicy 不强制。**这不是 calico 缺陷，是 orbstack acceptance 环境的 CNI 锁定限制。**

### 回滚恢复（已执行）
1. 节点删 `10-calico.conflist` + `calico-kubeconfig`（kubelet 回 orbstack 内置网络）。
2. `kubectl delete -f calico.yaml`（删 calico-node/kube-controllers/RBAC/CRD）。
3. 删 tigera operator 残留 CRD（`apiservers/imagesets/tigerastatuses.operator.tigera.io`）。

### 结论
- **orbstack acceptance 环境无法用 calico 替换内置 flannel**（orbstack 锁定 CNI）。calico 安装/回滚均验证此限制。
