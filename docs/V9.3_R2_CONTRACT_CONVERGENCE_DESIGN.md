## 0. 设计原则（用户裁定 + 评审修正）

1. **唯一权威 = 版本化 Contract Bundle**（不是纯 JSON Schema）：包含 JSON Schema + Semantic Invariants + Conformance Vectors + Manifest。
2. **contracts.py 是 Python binding**，不是独立权威源。
3. **禁止新建第二合同层**。
4. **分模型原子切换**（C 分批）。
5. **短期 ACL**：每个模型完成原子切换后**立即删除**该模型的 ACL，禁止长期双主运行。
6. **内部状态组合/引用权威实体**，禁止复制权威字段到端内 dataclass。

## 1. V1/V2 Wire Compatibility（评审 P0-1/P0-2）

### 1.1 冻结 V1 Wire Contract（不可破坏）
以下 V1 wire contract **保持不变**（本次 R2 不纳入改版）：
```text
- TrustedRequestContext / RunContext / OpsIntent（已签名 Context，改字段会破坏签名 payload）
- OpsAction / Verification
- ToolResult.success（V1 冻结联合语义：success: bool + status）
- Evidence / Hypothesis / PlanStep 的 V1 结构（作为 wire 兼容基线）
```

### 1.2 V2 只加不改（向后兼容）
- **V2 不删除、不重命名任何 V1 wire 字段**。
- V2 只**新增**字段（带默认值）或**新增**枚举值（不改变既有枚举的序列化值）。
- 例：`ToolResult` 的 V2 新增 `status_detail`（可选），但 `success` + `status` 的 V1 序列化保持不变。
- **版本协商**：payload 携带 `wire_version`（V1 恒为 "v1"）；V2 消费方必须能解析 V1 payload，V1 消费方对 V2 的**新字段忽略**、对**语义改变拒绝**。

### 1.3 bundle 版本 ≠ payload 版本
- `bundle_version`：Contract Bundle 自身的版本（`v1.0` → `v2.0`），用于工具链生成与校验。
- `wire_version`：wire payload 的版本（V1 冻结 / V2 扩展），与签名 Context 的版本独立。
- **结论**：`schema_version` 不直接写入已签名 Context payload；Context 版本保持冻结。

## 2. 唯一权威 = 版本化 Contract Bundle

### 2.1 Bundle 组成
```text
docs/contracts/bundle/v2/
  schema/                 # JSON Schema：结构/类型/枚举
    tool_result.json / evidence.json / hypothesis.json / plan.json / context.json
  invariants.md           # Semantic Invariants：跨字段和算法规则（human+machine 可读）
  conformance-vectors.json # Conformance Vectors：正/反测试向量（三端共享）
  manifest.json           # 版本、checksum、生成工具版本、参数
```

### 2.2 每类规则归属（评审 P0-3）
| 语义 | 承载位置 |
|------|---------|
| 结构/类型/枚举边界、必填/可选、UUID/时间/null | JSON Schema |
| fingerprint 哈希算法（输入含 tenant/cluster/run + canonical serialization + 字段顺序 + 时间归一化 + 摘要编码） | **Semantic Invariants**（跨语言 test vectors） |
| Evidence claim 规则（LLM source 拒绝、unknown 需 reason） | Semantic Invariants |
| 固定可靠性表（§三十六） | Semantic Invariants（三端同一表） |
| Hypothesis confirmed 条件（final≥0.80 + direct≥0.85 + 无 critical 矛盾） | Semantic Invariants |
| 预算消耗规则（max_steps/max_tools/max_latency 消耗顺序） | Semantic Invariants |
| 三端对同一 invalid vector 给出一致结果 | Conformance Vectors |

### 2.3 Conformance Vectors
```text
- positive: 每模型合法实例（含 V2 新字段可选）
- negative: unknown schema version / extra field / 缺必填 / 非法枚举 / 跨租户 fingerprint / LLM source
- 三端对同一 vector 给出一致 PASS/FAIL（Go 侧当前是 json.RawMessage，需先补齐严格模型）
```

## 11. 评审裁决修订（2026-08-21，方案 B 固定）★目标架构不可再改

> 用户裁定：**R2 目标架构固定为方案 B**。Evidence 必须保持 `evidence_id: UUID`、`provenance_fingerprint: string`。用固定 namespace 的 UUIDv5 从 fingerprint 确定性生成 evidence_id。Task1 曾把 `ToolResult.evidence_ids` 放宽为 `List[str]`，**已撤销**（恢复 UUID 引用）。

### 11.1 纠正三个错误判断（防复发）
1. **`evidence_id` ≠ fingerprint**。`Evidence.evidence_id` = 实体身份 UUID；`Evidence.provenance_fingerprint` = 事实去重键字符串。`evidence_hub.py` 把 `evidence_id = fingerprint` 是平行模型**错误合并**"实体身份"与"去重键"，R2 职责是拆开，而非放宽权威合同迁就错误实现。
2. **`test_p74` 用 `"ev-llm"` 不构成合同依据**。测试服从冻结合同，不反向冻结错误模型；现有非 UUID 测试数据随迁移修正。
3. **`ToolResult.evidence_ids` 是 V9.2 冻结字段，非 V2 新增**。它已存在于冻结合同、共享 fixture、Go/TS binding，是 Evidence UUID 引用。Task1 放宽为 `List[str]` 是 breaking contract drift，必须撤销（已撤销）。

### 11.2 方案 B 固定实现公式
```text
provenance_fingerprint = SHA256(canonical provenance fields)   # 去重键，字符串
evidence_id           = UUIDv5(FROZEN_EVIDENCE_NAMESPACE, provenance_fingerprint)  # 实体身份，UUID
fingerprint_index     : provenance_fingerprint → evidence_id
```
- 权威合同要求 UUID identity ✅
- 可复现确定性 evidence_id ✅（同 fingerprint 必同 UUID，去重仍成立）
- 跨 tenant/cluster/run 隔离 ✅（fingerprint 输入含隔离维度）
- Go/Python/TS 类型一致 ✅

### 11.3 实施前置修正（2026-08-21 整改后更新）★阻断项 3 修正
- `contracts.ToolResult.evidence_ids` 保持 `List[UUID]`（已恢复）。
- `tool_result.py.normalize_tool_result` 保持返回平行 ToolResult（未接权威，杜绝虚假收敛）。
- ACL（`acl/tool_result_ac.py`）证据引用规则（阻断项 4）：
  - 已是 UUID → 直接采用（对既有 Evidence 实体的引用）。
  - 非 UUID legacy 字符串 → 通过 `fingerprint_index`（fingerprint → evidence_id UUID）解析并**验证实体存在**；
    存在则返回该 UUID；**不存在/未提供 index → fail-closed（拒绝）**。
  - **禁止**为任意未知字符串无条件 UUIDv5 化——否则制造没有对应 Evidence 实体的悬空引用。
- UUIDv5 派生 `evidence_id` 只在 **Evidence 创建侧**（`evidence_hub`）进行：
  `evidence_id = UUIDv5(FROZEN_EVIDENCE_NAMESPACE, provenance_fingerprint)`。
- 序列化层输出 UUID 字符串；不触碰 V9.2 冻结字段类型。
