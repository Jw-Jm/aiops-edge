## 1. P7.9 Contract

### 职责

确认平台自身数据与外部 Kubernetes 平台能否通过 V9.2 建立的模型（`Cluster Registry /
tenant_clusters / credential_ref / platform-data-source config / canonical cluster`）映射进入
统一 Query。

### 核心原则（P7.9）

**不创建新的 source 身份或授权体系**。复用 V9.2 既有映射。

### 规则（P7.9）

```text
existing model sufficient
→ reuse only
→ no new table/service/error enum

missing one mandatory registration field
→ minimal extension in existing authoritative model
→ implement as Phase 7 change
→ preserve Gate 6 query semantics

requires new SoT / new identity authority / second query path
→ BLOCKED + Architecture Deviation
```

---

## 2. Data Source Mapping

```text
MySQL          → Authorization SoT（capability 鉴权 / identity 解析 / Cluster Registry）
VM             → observability.metrics.read → Tool: query_metrics
VLogs          → observability.logs.read    → Tool: query_logs
Query API      → AI Runtime data owner（统一查询入口）
外部平台        → 经 Cluster Registry / tenant_clusters / credential_ref 映射
```

### 约束

- 平台自身数据与已注册外部平台**使用相同 ToolResult 状态和 Evidence provenance**（P7.9）
- 外部平台不可达 → 现有 `unavailable` 语义（不新增 source authorization）
- 未知/未注册 Cluster 或无有效配置 → 现有 cluster/config `fail-closed` 语义

---

## 3. Model Sufficiency 判定

| 场景 | 处置 |
|------|------|
| 现有模型足够 | 复用，无新增表/服务/error enum |
| 缺 1 个强制注册字段 | 最小扩展（Phase7 change），保留 Gate6 语义 |
| 需要新 SoT/身份/第二查询路径 | **BLOCKED + Architecture Deviation** |

---

## 4. Test Plan（P7.9）

### T1 映射正确

- [ ] 平台自身数据（VM/VLogs）→ 正确 Tool/capability
- [ ] 已注册外部平台 → 经 Cluster Registry 映射到统一 Query

### T2 语义一致

- [ ] 平台自身 + 外部平台用相同 ToolResult 状态 / Evidence provenance
- [ ] 外部平台不可达 → `unavailable`

### T3 fail-closed

- [ ] 未知/未注册 Cluster → fail-closed
- [ ] 无有效配置 → fail-closed
- [ ] 映射指向错误 canonical cluster → 拒绝

### T4 模型充足性

- [ ] 现有模型足够 → 复用，无新增表/服务/error enum
- [ ] 需要新 SoT → BLOCKED + Architecture Deviation（不静默实现）

## 5. 验收条件
