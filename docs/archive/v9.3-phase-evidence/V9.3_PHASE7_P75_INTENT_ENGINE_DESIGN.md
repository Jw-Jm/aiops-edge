## 1. P7.5 Contract

### 职责

- **规范化用户调查意图**：把用户/系统触发转换为结构化 `Intent`，作为 Planner（P7.6）唯一输入。
- **歧义拒绝**：目标歧义 → `RESOURCE_AMBIGUOUS`（P7.5），**禁止猜**。
- **scope 预填**：Alert/Event/Change 只作为预填 scope/time/resource/symptom 的起点，**不自动创建 Run**（P7.8）。

### 输出（P7.5）

```text
intent
action_mode        // §28.2
target_type        // §28.3
resource
cluster scope
time range
symptom
ambiguity
```

### 边界

| 允许 | 禁止 |
|------|------|
| 解析用户显式意图 | 歧义时猜测/强行归因 |
| 预填 scope（来自 Alert/Event 上下文） | Alert/Event 自动创建 Run |
| 校验 tenant/cluster/capability scope | 扩大 scope |
| 标注 ambiguity → RESOURCE_AMBIGUOUS | LLM 自行生成 capability |

## 2. Intent Contract（Schema）

```text
Intent {
  intent_id            string
  intent               string   // 调查意图描述
  action_mode          enum     // read_only | plan_only | execute_allowed（§28.2）
  target_type          enum     // cluster|namespace|node|service|deployment|statefulset|
                                 // daemonset|pod|container|workload|host|vm|alert|trace|resource（§28.3）
  target_resource_id   string?  // nullable
  scope_kind           enum     // cluster / tenant / global
  primary_cluster_id   string?  // canonical cluster
  tenant_id            string   // canonical tenant
  time_range_start     time
  time_range_end       time
  symptom              string   // 症状描述
  ambiguity            string?  // 歧义说明（若有）
  capability           string   // 所需 capability（来自 Tool Registry，非 LLM 生成）
  source               enum     // user_explicit | approved_system_event（评审建议 1，仅预填不创建 Run）
  status               enum     // IntentCreated|EvidenceCollected|PlanGenerated|AwaitingApproval
}
```

### source（评审建议 1）

```text
source: user_explicit | approved_system_event
```
明确 Intent 来源，防止混淆自动事件。

### ambiguity 结构（评审建议 2）

```text
ambiguity: {
  status: RESOURCE_AMBIGUOUS,
  reason: [ multiple_clusters | missing_namespace | missing_time_range | ... ]
}
```
便于 Planner 判断澄清方向。

### Intent ≠ RunInvocation（评审建议 3）

```text
Intent
  ↓ user approval
RunInvocation
```
**Intent 不是创建 Run**；经用户批准后才进入 RunInvocation。

### action_mode（§28.2）

```text
read_only       // 只读调查（Phase7 默认）
plan_only       // 仅产出计划
execute_allowed // 允许执行（后续阶段，Phase7 不启用）
```

**Phase7**：Intent 的 `action_mode` 只能是 `read_only` 或 `plan_only`，`execute_allowed` 不启用。

### target_type（§28.3）

14 种：`cluster/namespace/node/service/deployment/statefulset/daemonset/pod/container/workload/host/vm/alert/trace/resource`。

## 3. Intent Classification

### 歧义处理（P7.5）

```text
目标可确定          → 生成 Intent
目标歧义            → RESOURCE_AMBIGUOUS（返回，需用户澄清）
证据不足            → 记录 unknown/missing_evidence（不强行归因）
```

**禁止**：歧义时猜 resource；证据不足时臆测根因。

### RESOURCE_AMBIGUOUS 语义

- HTTP/API 层：返回 `RESOURCE_AMBIGUOUS`（§错误码），附候选 resource 供用户选择
- Intent 状态：停在 `IntentCreated`，等待澄清，不进入 Planning

---

## 4. Context Binding（scope 预填与收敛）

### 人工显式触发（P7.8 边界）

```text
Alert/Event/Change exists
   ↓
（用户点击"交给 AI 调查"显式按钮）
   ↓
Intent Engine 预填 scope/time/resource/symptom
   ↓
用户确认后创建 Run（经人工触发）
```

**禁止**：页面加载 / 告警到达 / 事件刷新自动创建 Run（P7.8/P12.2）。

### scope 收敛

- Intent 的 `tenant_id`/`cluster_id` 必须是 canonical（7ed01afc.../91771a6e...）
- 签发 TrustedRequestContext V2 的 scope = Intent scope，**不自动扩大**
- `capability` 来自 Tool Registry（非 LLM 生成，P7.2 约束）

---

## 5. State Machine

```text
IntentCreated
   ↓
EvidenceCollected
   ↓
PlanGenerated
   ↓
AwaitingApproval        ← Phase7 边界（到此为止）
   ↓
Approved                ← 后续阶段
   ↓
Executed                ← 后续阶段
```

**Phase7**：Intent/Planner 只推进到 `AwaitingApproval`，`Approved`/`Executed` 属于后续阶段。

## 6. Test Plan（P7.5）

### T1 意图解析

- [ ] 明确的 cluster/service/时间窗 → 生成结构化 Intent
- [ ] `action_mode`/`target_type` 枚举合法
- [ ] 缺 time_range → 默认/校验

### T2 歧义处理

- [ ] 目标歧义 → `RESOURCE_AMBIGUOUS`，不猜
- [ ] 证据不足 → `unknown`/`missing_evidence`，不强行归因
- [ ] 歧义时停在 `IntentCreated`，不进入 Planning

### T3 Scope 收敛

- [ ] tenant/cluster 必须是 canonical（非 canonical → 拒绝）
- [ ] capability 来自 Tool Registry（LLM 注入 → 拒绝）
- [ ] scope 不自动扩大

### T4 Manual Trigger（P7.8）

- [ ] Alert/Event 到达**不**自动创建 Run
- [ ] 用户显式触发才创建 Run
- [ ] Alert/Event 仅预填 scope/time/resource/symptom

### T5 State Machine

- [ ] IntentCreated → EvidenceCollected → PlanGenerated → AwaitingApproval 迁移正确
- [ ] Phase7 不进入 Approved/Executed

### T6 Capability Non-Creation（评审建议）

- [ ] 用户要求 "执行 kubectl delete" → `action_mode=plan_only`，`capability` 来自 Registry
- [ ] LLM 试图生成 `k8s.delete` 等不存在 capability → 拒绝
- [ ] `capability` 仅在 Tool Registry 中存在才可用
