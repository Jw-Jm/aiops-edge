## 1. Phase 9 契约与边界

### 职责

Phase 9 在 V9.3 链中的位置：

```text
Intent → Plan → Tool → ToolResult → Evidence → Hypothesis → Support → Contradiction
   → Missing → Follow-up → Re-score → Root Cause → Confidence → Unknowns →（Gate 9 停止）
```

Phase 9 负责将既有 Phase 7/8 的 **Evidence**（事实）加工为 **Root Cause / Confidence / Unknowns**（结论），是"证据 → 结论"的唯一正式 RCA 路径。

### 边界

| 允许 | 禁止 |
|------|------|
| 生成多个 Hypothesis candidate | 直接生成 confirmed root cause |
| 结构化 Evidence→Hypothesis 支持关系 | 同一 provenance 重复加权提分 |
| 主动搜索反证（contradiction） | prompt-only RCA |
| 明确 critical/optional missing | 用语言润色掩盖 missing critical |
| follow-up 受全局 budget 约束 | follow-up 开启第二调查图 |
| 冻结 V1 公式评分，结果可复算 | LLM 直接给最终 confidence 数字 |
| 排序输出 score/support/contradictions/missing | 跳过 confirmed 阈值条件 |
| Timeline + First Bad Event 时间推断 | First Bad Event 默认等于 Alert/Change |
| unknown-safe 行为（root_cause=unknown） | 无法达阈时自动 remediation |

**红线（贯穿 P9）**：
- **F3 Evidence 边界**：LLM inference 不作为 Evidence；Hypothesis 是独立实体，不是 claim_type。
- **F4 Planner 唯一控制**：follow-up 仍由唯一 Planner 控制，Agent/Hypothesis 不开启第二调查图。
- **F5 不触发执行**：P9 停在 Root Cause / Unknowns，不进入 Structured OpsAction / 执行（属 Phase 11）。
- **固定公式**：confirmed 必须满足 §四十（final_score>=0.80 AND >=1 direct evidence reliability>=0.85 AND no unresolved critical contradiction）。

## 2. P9.1 RCA Input Snapshot

每轮 RCA 基于明确 Evidence snapshot，禁止 LLM 在 scoring 中引入未登记事实。

```text
RcaInputSnapshot {
  run_id            string
  intent_id         string
  evidence_ids      [string]   // 本轮参与 RCA 的 Evidence IDs（冻结）
  snapshot_version  string     // Evidence 版本/时间
  generated_at      time
  source            enum       // evidence_hub（唯一事实来源）
}
```

**关键约束**：
- snapshot 记录参与 RCA 的全部 Evidence IDs + version/time。
- **scoring 只能引用 snapshot 内 Evidence**；未登记事实（LLM 自述/外部猜测）→ 拒绝。
- 快照不可变：同一 snapshot 必须产生可复现的评分分量（Gate 9 断言 1）。

## 3. P9.2 Hypothesis Generator

生成多个 candidate，禁止直接生成 confirmed root cause。

```text
Hypothesis {
  hypothesis_id         string
  run_id                string
  claim                 string   // 因果断言（非事实）
  affected_resource     string   // cluster_id + resource_id + namespace/service
  expected_mechanism    string   // 预期作用机制
  required_support      [EvidenceType]  // 需要哪些证据类型支撑
  potential_contradiction [string]      // 可能存在的反证方向
  status                enum     // candidate|supported|confirmed|rejected|unknown
  created_by            enum     // hypothesis_generator（规则/LLM 生成，但结论判定仅靠公式）
}
```

**关键约束**：
- 生成**多个** candidate（>1），每轮 RCA 不预设唯一答案。
- 每个 hypothesis 必须包含：claim / affected_resource / expected_mechanism / required_support / potential_contradiction。
- **不输出 final root cause**（`status` 起始为 `candidate`，最终状态由 P9.8 Ranker 判定，不由生成器预设）。
- 生成器可提示候选方向，但**最终 confirmed 判定完全由公式决定**，LLM 不能直接标记 confirmed。

## 4. P9.3 Support Matcher

把 Evidence→Hypothesis 支持关系结构化，计算 evidence support；同一 provenance 重复 Evidence 不重复加权（§三十八）。

```text
SupportRelation {
  support_id       string
  hypothesis_id    string
  evidence_id      string     // 必须 ∈ RCA Input Snapshot
  relation         enum       // direct_support=1.0 | indirect_support=0.6
  source_reliability float     // 从 Evidence.reliability 读取（§三十六）
}
```

**support 计算（§三十八）**：

```text
evidence_support =
  Σ(source_reliability × relation_weight)
  /
  Σ(source_reliability)

关系权重: direct_support=1.0, indirect_support=0.6
上限: top 5 unique supporting evidence
```

**关键约束**：
- 同一 provenance 的重复 Evidence → 同一 evidence_id，**不重复加权**（复用 Evidence Hub 去重）。
- **禁止用大量低价值证据堆分**（只取 top 5 unique supporting evidence）。
- evidence_support 需能复算（输入证据集 + 权重 → 输出数值确定）。

## 5. P9.4 Contradiction Checker

主动搜索反证。

```text
Contradiction {
  contradiction_id    string
  hypothesis_id       string
  evidence_id         string     // 产生反证的 Evidence
  contradiction_type  enum
  severity            enum       // critical | normal
  resolved            bool       // 是否已解决
  description         string
}
```

**contradiction_type（§四十 + §三十九）**：
- `time_conflict`        时间矛盾（事件发生在异常之后 → 不可能是原因）
- `resource_cluster_conflict`  资源/cluster 矛盾（不同资源/跨 cluster）
- `metric_log_trace_conflict`  指标与日志/trace 矛盾
- `change_after_fault`   变更发生在故障后（不可能是原因）
- `temporal_relation_weak`  时间关系弱/无时间支持

**severity 规则**：
- `critical`：直接推翻假设（如事件发生在故障后、跨 cluster、指标与日志相矛盾且不可调和）。
- `normal`：削弱但非推翻。

**关键约束**：
- **unresolved critical contradiction → 不得 confirmed**，无论 score 多高（§四十铁律）。
- 时间矛盾判定遵循 §三十九 temporal relation：候选事件发生在异常之后 → temporal_relation=0.00 → contradiction。

## 6. P9.5 Missing Evidence Engine

每条 hypothesis 明确 critical/optional missing。critical missing 限制最终状态，不得用语言润色掩盖。

```text
MissingEvidence {
  missing_id        string
  hypothesis_id     string
  required_type     EvidenceType
  critical          bool     // critical=true 会限制最终状态
  reason            enum     // insufficient_data|permission_denied|unavailable_source|expired_evidence
  followup_slot     string   // 对应的补查 tool_id/capability（交 P9.6）
}
```

**关键约束**：
- 每条 hypothesis 必须明确列出 `critical` / `optional` missing。
- **critical missing → 无法 confirmed**（即使分数达标，missing critical evidence category 会 penalty -0.20 each，cap -0.40，且最终状态受限）。
- **不得通过语言润色掩盖 missing**：`root_cause=unknown` + `missing_evidence=explicit`（P9.10）。
- reason 复用 Evidence claim_type=unknown 的冻结枚举（§三十四）。

---

## 7. P9.6 Follow-up Planner

只针对 missing evidence 新增步骤，仍由唯一 Planner 控制并受全局 budget。follow-up 不能开启第二调查图。

```text
FollowUpRequest {
  followup_id      string
  hypothesis_id    string
  missing_id       string      // 对应 P9.5
  tool_id          string      // 已注册 Tool（P7.1）
  capability       string
  budget_cost      int         // 计入全局 budget
  status           enum        // proposed|accepted|rejected|completed
}
```

**关键约束**：
- **只针对 missing evidence 新增步骤**，不无限追加探索。
- **仍由唯一 Planner 控制**：follow-up 步骤并入既有 DAG，不开启第二调查图（Agent/Hypothesis 不自主调度）。
- **受全局 budget**：max_steps/max_tools/max_latency 冻结；超限 → `budget_exceeded` 终止。
- 补查产生的新 Evidence 需回填到 RCA Input Snapshot（Re-score 用新快照）。

## 8. P9.7 Fixed Scoring

严格使用冻结公式（§三十七）与 reliability（§三十六）；输出各分项和 penalty，结果可复算。禁止 LLM 直接给最终 confidence 数字。

```text
ScoreBreakdown {
  hypothesis_id          string
  base_score             float
    llm_reasoning_prior  float   // × 0.35
    evidence_support     float   // × 0.30
    source_reliability   float   // × 0.20
    temporal_relation    float   // × 0.15
  penalties              [Penalty]
  final_score            float   // clamp(base_score - penalties, 0, 1)
  confidence_state       enum    // confirmed|supported|rejected|unknown
}

Penalty {
  type       enum    // critical_contradiction|normal_contradiction|missing_critical
  value      float   // 见下
  reason     string
}
```

**base_score（§三十七）**：

```text
base_score =
    llm_reasoning_prior × 0.35
  + evidence_support    × 0.30
  + source_reliability  × 0.20
  + temporal_relation   × 0.15
```

**Penalty 表（§三十七）**：

```text
critical contradiction         -0.25 each, cap -0.50
normal contradiction           -0.10 each, cap -0.30
missing critical evidence      -0.20 each, cap -0.40
```

**final_score（§三十七）**：

```text
final_score = clamp(base_score - penalties, 0, 1)
```

**temporal_relation（§三十九 固定值）**：

```text
1.00  原因明显先于 First Bad Event，且位于同一资源或直接依赖链
0.70  原因先于异常，并位于合理相关时间窗
0.40  时间关系弱、只能证明相关
0.00  无时间支持，或候选事件发生在异常之后
```

**source_reliability（§三十六 固定表）**：

```text
Kubernetes API current state     0.95
Metric / SLI                     0.95
Trace / Span                     0.90
Kubernetes Event                 0.90
Structured Change Record         0.90
Resource Graph deterministic     0.85
DeepFlow observation             0.85
Raw Log                          0.85
Log Pattern                      0.80
K8sGPT Diagnosis                 0.70
Runbook / SOP                    0.65
Historical Case                  0.60
LLM inference                    NOT Evidence
```

**关键约束**：
- 所有数值来自冻结的 V1 配置，**DeepSeek 不得为过测试调高**。
- **禁止 LLM 直接给最终 confidence 数字**：LLM 只可生成 hypothesis 候选（P9.2），数值全部由公式计算。
- 输出各分项 + penalty，**同一 snapshot 可复算**（Gate 9 断言 1）。
- 只要存在 unresolved critical contradiction → 不得 confirmed（无论 score 多高）。

## 9. P9.8 Root Cause Ranker

排序时输出：score、support、contradictions、missing、confidence state。confirmed 必须满足原文条件（§四十）。

```text
RootCauseRanking {
  run_id           string
  hypotheses       [RankedHypothesis]   // 按 final_score 降序
  root_cause       RankedHypothesis | null
  confidence_state enum
  unknowns         [Unknown]
}

RankedHypothesis {
  hypothesis_id    string
  final_score      float
  support          float   // evidence_support
  contradictions   [Contradiction]
  missing          [MissingEvidence]
  confidence_state enum    // confirmed|supported|rejected|unknown
}
```

**confirmed 判定（§四十）**：

```text
final_score >= 0.80
AND >=1 direct evidence reliability >= 0.85
AND no unresolved critical contradiction
```

**supported 判定（§四十）**：

```text
0.60 <= final_score < 0.80
```

**关键约束**：
- 排序输出完整字段（score/support/contradictions/missing/confidence state）。
- **confirmed 必须满足三条原文条件**，缺一不可。
- root_cause 只在存在 confirmed hypothesis 时输出；否则 `root_cause=unknown`。

## 10. P9.9 Timeline / First Bad Event

统一 change/event/log-pattern/trace/metric/alert/execution 的时间轴；First Bad Event 是时间推断结果，不默认等于 Alert 或 Change。

```text
Timeline {
  run_id         string
  events         [TimelineEvent]   // 按 observed_at 升序
  first_bad_event TimelineEvent | null
}

TimelineEvent {
  event_id       string
  event_type     enum   // change|event|log_pattern|trace|metric|alert|execution
  observed_at    time
  resource_id    string
  source         enum   // Evidence.source
}
```

**关键约束**：
- 统一多类事件（change/event/log-pattern/trace/metric/alert/execution）到**单一时间轴**。
- **First Bad Event 是时间推断结果**，不默认等于 Alert 或 Change（需按 observed_at 最早 abnormal 判定）。
- 为 temporal_relation（§三十九）提供时间依据：候选事件发生晚于 First Bad Event → temporal_relation=0.00。
- 时钟严重偏差 → temporal_relation=partial/unknown，不得强行给 1.0。

---

## 11. P9.10 Unknown-safe Behavior

无法达到阈值或 critical evidence 缺失时：

```text
root_cause = unknown
missing_evidence = explicit
no automatic remediation
```

**关键约束**：
- `root_cause=unknown` 是**显式合法状态**，不是失败。
- `missing_evidence` 必须显式列出（不通过语言润色掩盖）。
- **no automatic remediation**：P9 不产生任何 Structured OpsAction / 执行动作（F5）。
- 与 Phase 11 边界：`unknown` 状态不能触发自动补救。

## 13. 与既有组件契约对齐

| 既有契约 | P9 消费方式 |
|---------|------------|
| P7.4 Evidence Hub | P9.1 snapshot 引用 Evidence IDs；P9.3 读 reliability；P9.5 复用 reason 枚举 |
| P7.6 Planner（唯一 DAG） | P9.6 follow-up 并入既有 DAG，不开启第二图 |
| P8.1 AgentRuntime | P9 分析消费 AgentRuntime 产生的 ToolResult/Evidence |
| ARI.4 AgentInsight | Hypothesis candidate 可由 AgentInsight.insights 驱动（evidence_confidence 为支持素材，非根因概率） |
| §三十六 reliability | P9.7 source_reliability 分量直接读取 |
| §三十九 temporal_relation | P9.9 Timeline 提供时间依据 |

**重要澄清**：
- **Hypothesis ≠ AgentInsight ≠ Evidence**：
  - Evidence = 事实（LLM inference 绝不进入）。
  - AgentInsight = Agent 领域洞察（evidence_confidence，非根因概率）。
  - Hypothesis = P9 因果候选（claim/affected_resource/mechanism），由公式判定状态。
- **Agent 不成为 Root Cause 决策者**：Agent 只提供 insight 素材，最终 confirmed 判定完全由 P9.8 公式决定。
