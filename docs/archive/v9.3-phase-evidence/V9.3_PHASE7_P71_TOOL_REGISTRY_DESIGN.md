## 1. P7.1 Contract

### 职责

- **统一工具描述**：登记所有 Agent 可用的查询能力。
- **注册不执行**：Tool Registry 只做元数据注册与 capability gate，不做数据访问。
- **Planner 选择约束**：Planner 只能选择「已注册 + 当前 Cluster 可用 + 当前 Principal 有
  capability」的 Tool（§30）。
- **Tool ≠ Data Owner**：Tool 声明 `owner`（数据所有者，如 `query-api`），Agent 不能通过
  注册 Tool 自定义数据源。

### 边界

| 允许 | 禁止 |
|------|------|
| 登记 ToolDefinition（只读查询类） | 未注册 Tool 执行 |
| 声明 capability / risk / scope | Agent 自带隐藏 Tool |
| capability gate（§31 映射） | Planner/LLM 修改映射（§31） |
| 只读查询 Tool | 自动执行 / 自动批准 |

### 非目标（本 P7.1 不做）

- ❌ 不执行任何 Tool（执行在后续 RunInvocation 阶段）
- ❌ 不引入自动调用链
- ❌ 不新增第二 SoT / 第二资源发现

## 2. ToolDefinition Schema

### 字段定义

```text
ToolDefinition {
  tool_id             string   // 唯一 id，如 "query_logs.v1"
  version             string   // 版本（语义化）
  contract_version    string   // schema 契约版本，默认 "v1"（评审建议，预留兼容）
  domain              enum     // observability / kubernetes / knowledge / changes / execution
  name                string   // 唯一名称
  category            string   // 分类（查询/诊断/执行）
  description         string   // 人类可读描述
  owner               string   // 数据所有者（如 "query-api"），Tool ≠ Data Owner（v0.2）
  lifecycle_status    enum     // draft / active / deprecated / disabled（评审建议 1）
  read_only           bool     // 是否只读（Phase7 查询类必须 true）
  baseline_risk       enum     // R0..R4（§28.8），激活后不可降低（immutable）
  risk_level          enum     // 运行时风险（与 baseline_risk 并存，P7.1 合同）
  evidence_required   bool     // 是否必须产出 Evidence 对象（评审建议 2，查询/执行类均 true）
  capability          string   // 所需 capability（映射 §31）
  required_capability string   // P7.1 合同必需（等价 capability）
  availability        enum     // per-cluster 可用性
  allowed_scope       enum     // cluster / tenant / global
  input_schema        object   // 输入 JSON Schema
  output_schema       object   // 输出 JSON Schema
  timeout_class       enum     // fast / medium / slow
  timeout             duration // 超时
  retry               int      // 重试上限
  backend             enum     // query-api / k8sgpt / knowledge
  planner_selectable  bool     // 是否可被 Planner 选择
  automatic           bool     // 是否自动（Phase7 只读工具可 true，执行类必须 false）
}
```

### lifecycle_status（评审建议 1）

```text
draft       // 草稿，不可选
active      // 激活，可选（受 gate 约束）
deprecated  // 已弃用，不再新增使用（保留兼容）
disabled    // 禁用，不可选/不可执行
```

用于新旧 Tool 并存、capability 迁移、版本淘汰——避免直接删除 Tool 破坏既有引用。

### evidence_required（评审建议 2）

```text
query_logs    → evidence_required: true
execute_shell → evidence_required: true
```

所有 Tool 结果都应进入 Evidence 对象（与 P7.4 Evidence Hub 契约关联）。

### risk 枚举（§28.8）+ Phase7 默认

```text
R0  read-only observability get/list                → 自动
R1  diagnostic / describe / top / K8sGPT            → 自动 + audit
R2  restart / small safe scale-up                   → 用户本人显式 confirmation
R3  configuration/resource/deployment 修改          → 独立 approver approval
R4  destructive/storage/network/restricted shell    → 严格审批或默认阻止
```

### 必填约束

- Phase7 查询类 Tool：`read_only=true`、`planner_selectable` 可按需、`automatic` 可 true
- 执行类 Tool（execute_k8s/execute_shell）：`baseline_risk=R4`、`planner_selectable=false`、
  `automatic=false`（§30 固定）

### Risk 单向升级（评审建议 3）

- 允许：`R1 → R2 → R3 → R4`（升级）
- **禁止**：激活后降低风险等级（`R4 → R2` 或 `execute_shell.risk_level: R1` 配置绕过）
- 约束：**`risk_level` 在 `lifecycle_status=active` 后 immutable**。capability/risk 修改需重新审批。

## 4. Tool → Capability 映射（§31，Planner/LLM 不得修改）

```text
query_metrics     → observability.metrics.read
query_logs        → observability.logs.read
query_traces      → observability.traces.read
query_alerts      → observability.alerts.read
query_topology    → observability.topology.read

execute_shell     → execution.*
```

映射表为**只读契约**，Planner/LLM 不得修改（§31）。每次 Tool 选择需做 capability gate：
`required_capability ∈ 当前 Principal 的 capability ∩ allowed_scope`.

## 5. 注册与执行边界

### 注册

- ToolDefinition 以**声明式清单**维护（非代码硬编码），Registry 提供注册/校验/查询接口。
- 未注册 Tool：Planner 不可见，不可执行。

### 选择（Planner gate，§30）

```text
Tool selectable ⟺
   registered(registry) ∧
   lifecycle_status=active ∧
   available(cluster) ∧
   owner_policy_allowed(owner 授权策略允许) ∧   // 评审建议 4
   capability.required ⊆ principal.capability ∧
   allowed_scope 覆盖请求 scope ∧
   planner_selectable=true
```

**owner_policy_allowed（评审建议 4）**：`owner` 不仅是标签，还需有**授权策略约束**——
数据所有者（如 query-api）通过策略声明哪些 capability/scope 允许访问，Planner gate 校验之，
避免 `owner` 退化为纯标签。

### 执行边界

- Phase7：Tool 仅被 InternalQueryClient（P7.2）调用，经 TrustedRequestContext V2 鉴权。
- 执行类（R2+）：需人工 approval；R4 默认阻止。

## 6. Test Plan（P7.1）

> TDD 风格：先写测试，再实现。以下为测试设计（实现待批准）。

### T1 注册与校验

- [ ] 合法 ToolDefinition 注册成功
- [ ] 缺 `required_capability` / `allowed_scope` / `read_only` 字段 → 校验失败
- [ ] `contract_version` 缺省 → 默认 "v1"
- [ ] 重复 `tool_id` → 拒绝

### T2 Capability gate（§31）

- [ ] 无 capability 的 Principal 选 Tool → 拒绝
- [ ] `required_capability ⊆ principal.capability` 才可选
- [ ] `allowed_scope` 不覆盖请求 scope → 拒绝
- [ ] 映射表只读，Planner 尝试修改 → 失败

### T3 Planner 选择约束（§30）

- [ ] 未注册 Tool → 不可选
- [ ] cluster 不可用 Tool → 不可选
- [ ] `planner_selectable=false`（execute_k8s/execute_shell）→ 不可被 Planner 选
- [ ] 只读 Tool 选择成功；执行类 Tool 默认不可选

### T4 边界安全

- [ ] 只读查询 Tool `read_only=true` 强制（误配 false → 校验失败）
- [ ] execute_k8s/execute_shell 固定 `baseline_risk=R4` + `planner_selectable=false` + `automatic=false`
- [ ] Agent 无法注册隐藏 Tool（Registry 是唯一入口）
- [ ] Tool 声明 `owner` 与 backend 一致（Tool ≠ Data Owner）
- [ ] `owner_policy_allowed` gate：owner 策略不允许 → 不可选（评审建议 4）

### T5 Registry Integrity（评审建议 5）

- [ ] 不兼容的 `contract_version`（v1 Tool 被 v2 contract 覆盖）→ 拒绝
- [ ] `risk_level` 激活后降级（active → 降低）→ 拒绝
- [ ] active Tool 修改 capability / risk / owner → 需重新审批，否则校验失败
- [ ] `lifecycle_status` 变更（active→deprecated）不影响已引用 evidence
- [ ] 执行类 Tool 无法通过配置绕过 R4（如设 `risk_level: R1`）→ 拒绝
