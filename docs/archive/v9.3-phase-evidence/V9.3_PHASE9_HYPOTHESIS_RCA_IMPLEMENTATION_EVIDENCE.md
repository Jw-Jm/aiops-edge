# 评审退回 Remediation（2026-08-21，Gate 9 FAIL → 修复）

## 13. 评审 P0 逐条闭环

### P0-1 新 RCA 未接入生产主链
- 建立 `rca_engine.py`（单一 RCA 编排器）：Evidence → Hypothesis → Support → Contradiction(derive) → Missing(derive) → Scoring → Ranker → Timeline → Unknown-safe。
- 建立 `rca_production.py`（生产适配器）：返回结构与 `full_rca_analysis` 兼容（`mode/result/root_cause/confidence`），内部走 RcaEngine，禁止绕过 Evidence。
- **边界**：生产调用点（`/api/v1/ops/rca*`、`node_rca`）实际接线需真实 query-api 数据构造 Evidence，属后续真实环境 Integration Gate（In-memory MVP 无真实数据）。

### P0-2 评分输入可伪造
- `ScoringEngine.score()` 改为只接受 `RcaEvaluationInput`（结构化），不再接受裸 support/reliability/temporal。
- 分量全部内部计算：evidence_support ← SupportMatcher；source_reliability ← unique reliability 均值；temporal_relation ← Timeline；penalty ← ContradictionChecker/MissingEvidenceEngine。
- score 前校验所有 supporting evidence 已登记到 RcaInputSnapshot（禁未登记事实）。调用方传裸分量 → `ScoringError`。

### P0-3 Hypothesis 双模型 + 缺强隔离
- `hypothesis.py` Hypothesis 增加 run_id/tenant_id/cluster_id/resource_id 强隔离（必填）。
- `affected_resource` 不再塞症状文本；改用规范 `resource_id`。
- 单一正式 Phase 9 Hypothesis 实体（RcaEngine 唯一使用）。

### P0-4 Follow-up 是第二套 Planner
- `planner.py` 增加 `add_followup_step()`（共享原 Plan DAG + budget + Registry 校验）。
- 校验：Tool 注册且 active、capability 匹配 required_capability、max_followup_rounds（默认 2）、max_total_steps（默认 20）、max_steps。
- 独立 `followup_planner.py` 保留为兼容遗留，RcaEngine 用 Planner 的 follow-up 能力。

### P0-5 反证/缺失未主动检测
- `ContradictionChecker.detect()`：从 Evidence/Hypothesis/Timeline 主动推导（cross-cluster、change_after_fault、metric-log-trace conflict、temporal weak）。
- `MissingEvidenceEngine.derive()`：从 Hypothesis.required_support vs 实际 Evidence 类型推导缺失类别。

### P0-6 冻结 Source Reliability 未落实
- `rca_engine.py` 维护 `SOURCE_RELIABILITY_V1`（§三十六 固定表）：metric/k8s_state=0.95、trace/k8s_event/change=0.90、topology/resource/hardware/log_error=0.85、log_pattern/capacity=0.80、knowledge_case=0.60。

## 14. 评审 P1 逐条闭环

### P1-1 Timeline 状态语义
- `TimelineEvent` 增加 cluster_id/evidence_id（合同要求）。
- `first_bad_event` 只取最早"异常"事件（默认异常类型集 + abnormal 标记），不默认最早事件。
- `temporal_relation=1.0` 需同一资源/直接依赖链；时钟偏差不强行给 1.0。

### P1-2 Ranker 状态矩阵
- 低分(<0.60) → unknown（非 rejected）；rejected 仅用于 unresolved critical contradiction。
- 高分但缺直接 evidence → unknown（非 rejected）。

### P1-3 快照不可变
- `RcaInputSnapshot.evidence_ids` 改为 tuple（不可变，禁原地 append/remove）。
- 补查生成新 snapshot 时 `snapshot_version` 递增（v1→v2）。
