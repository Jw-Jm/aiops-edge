## 1. Phase7 Boundary Contract

### 允许（Phase7 能力扩展）

- ✅ 查询能力扩展（统一事实查询）
- ✅ 工具注册（Tool Registry，注册不执行）
- ✅ 证据组织（Evidence Hub，组织不判断）
- ✅ 计划生成（Planner，产出 Plan Proposal 非 Execution Command）
- ✅ Agent 生命周期管理（contract/schema/lifecycle）

### 禁止（V9.3_FROZEN 红线）

- ❌ 自动执行 Kubernetes action / 自动修改资源
- ❌ AI 自动触发 Run / 绕过 approval / 自动扩大 scope
- ❌ 新建第二 SoT（第二 CMDB / Cluster Registry / Tenant Registry）
- ❌ 改变执行安全边界（RunInvocation / RunControl / TrustedRequestContext 三 Context 分离）
- ❌ 引入自动执行链（Alert → AI → kubectl/action）

### 人工显式触发覆盖（V9.3_FROZEN）

```text
Alert/Event
    ↓
AI Analysis（只产出 Suggestion）
    ↓
Human Explicit Trigger（用户显式批准）
    ↓
RunInvocation
    ↓
Execution
```

不允许变成：`Alert → AI → action`。

### Capability Boundary Matrix（Phase7 能力边界）

提前冻结各能力的默认行为，避免 Agent Runtime 误将"Planner 有计划"理解为"Executor 有权限"：

| 能力 | Phase7 允许 | 默认行为 |
|------|:---:|------|
| 查询 Metrics | ✅ | read-only |
| 查询 Logs | ✅ | read-only |
| 查询 Trace | ✅ | read-only |
| 生成诊断建议 | ✅ | human review（产出 Suggestion） |
| 创建 RunInvocation | ❌ | 仅人工显式触发 |
| Kubernetes restart | ❌ | 未进入 Phase7 |
| 自动扩缩容 | ❌ | 禁止 |
| 自动修复 | ❌ | 禁止 |

**边界原则**：`Planner 有计划 ≠ Executor 有权限`。所有执行类能力不在 Phase7 范围内。

## 2. Tool Plane（P7.1 + P7.2 + P7.3）

### 架构域

Tool Plane 提供统一的**只读查询工具**抽象，是 Agent 获取事实的唯一通道。Planner/Agent
只能通过已注册 Tool 查询，不能直接访问 VM/VLogs/MySQL。

### P7.1 Tool Registry

**职责**：统一工具描述，**注册不执行**。

**ToolDefinition**（§三十 + P7.1，字段名注意 V9.3 中 `risk_level` 与 P7.1 `baseline_risk` 并存）：
```text
ToolDefinition {
  tool_id, version, domain
  name, category, description
  owner                       // Tool 能力所有者（如 query-api），避免 agent 自定数据源
  read_only, risk_level, availability
  input_schema, output_schema
  timeout_class, retry, backend
  required_capability, allowed_scope
  planner_selectable, automatic
}
```

**`owner` 字段**：声明 Tool 能力的**数据所有者**（如 `owner: query-api`）。**Tool 是能力注册，
不是数据拥有者**——agent 不能通过注册 Tool 来"自己定义数据源"。

**risk 枚举（§28.8）+ 执行策略（§四十七）**：
```text
R0  read-only observability get/list                → 自动
R1  diagnostic / describe / top / K8sGPT            → 自动 + audit
R2  restart / small safe scale-up                   → 用户本人显式 confirmation
R3  configuration/resource/deployment 修改          → 独立 approver approval
R4  destructive/storage/network/restricted shell    → 严格审批或默认阻止
```

**Tool→Capability 映射（§三十一）**：每个 Tool 必须声明 `required_capability`，映射到
§十六 Capability。Planner 只能选择**已注册 + cluster 可用 + capability 允许**的 Tool。

**边界**：Planner/Agent **不能**直接调用未注册 Tool；`automatic=false` 的 Tool 只能人工显式触发。

### P7.2 InternalQueryClient + TrustedContextIssuer

**职责**：query-api 的受控查询客户端。Agent 通过 InternalQueryClient 向 `/internal/v1/query/*`
发起查询，用 TrustedContextIssuer 签发 TrustedRequestContext V2（复用 `fQmL5...` trust root）。

**边界**：InternalQueryClient 只允许调用**已注册 Tool 映射的查询端点**；签发 context 严格
按 RunInvocation/RunControl 约束，不扩展 scope。

### P7.3 ToolResult Normalization

**职责**：统一 Tool 返回结构，语义准确。

**ToolResult（§三十二）**：
```text
ToolResult {
  tool_name, cluster_id
  status, summary, data
  error_code, error_message, retryable
  evidence_ids, source_system, query_id, time_range
  started_at, finished_at
}
```

**status 枚举（§28.4）**：`success / partial / no_data / failed / timeout / unavailable / permission_denied`

**normalization 规则（§三十二 + P7.3）**：
```text
tool successful + empty result  → no_data
binary missing / backend unreachable → unavailable
authorization reject            → permission_denied
deadline exceeded               → timeout
backend query error             → failed
```

**禁止（P7.3 / §94）**：`permission_denied→no_data`、`no_data→healthy`、`unavailable→healthy`、
backend 403 不得变 no_data、network error 不得变 no_data。

### Tool Plane 数据流

```text
Agent/Planner
   ↓ (select registered tool)
Tool Registry (metadata + capability gate)
   ↓
InternalQueryClient → TrustedContextIssuer
   ↓ TrustedRequestContext V2
query-api /internal/v1/query/*
   ↓
VM / VLogs
   ↓
ToolResult normalization → evidence_ids
   ↓
Evidence Hub
```

### Tool Plane 验收条件

- [ ] 只读 Tool 全部 `read_only=true`，无写/执行类 Tool
- [ ] 每个 Tool 声明 `required_capability`，Planner 选择受 capability gate 约束
- [ ] `permission_denied` 不降级为 `no_data`
- [ ] 未注册 Tool 无法被 Planner 选择

## 3. Evidence Plane（P7.4 Evidence Hub）

### 架构域

Evidence Hub 统一组织查询证据，**只保存/关联/追踪，不判断执行**。

### Evidence 对象（§三十三）

```text
Evidence {
  evidence_id, run_id
  tenant_id, cluster_id
  evidence_t            // 时间戳
  source                // source_system（VM/VLogs/MySQL/Query API）
  query                 // 原始查询
  result                // ToolResult data 摘要
  hash                  // 结果指纹（确定性 hash）
  confidence            // 来源可靠性
  provenance            // 溯源链
  status                // created / validated / expired / archived
}
```

### Evidence 生命周期

```text
Evidence
   ↓
created    // 查询产生，尚未校验
   ↓
validated  // 已核对来源/hash，可用于推理
   ↓
expired    // 超出时效，不再视为当前事实
   ↓
archived   // 归档保留（审计），不参与活跃推理
```

**关键语义**：AI Agent 推理必须区分证据时效——**旧证据 ≠ 当前事实**。`expired`/`archived`
证据不得作为 live fact 依据。

### 关键约束

- **不改变 SoT**：Evidence Hub 是证据索引层，不复制/不修改 VM/VLogs/MySQL 数据。
- **provenance 与 source 无关**（P7.9）：平台自身 / 外部 source 用相同证据链。
- **LLM inference ≠ live fact**（DoD #94 / #101）：Evidence 只记录查询事实，AI 推断作为
  独立 finding，不得标记为 live fact。
- **去重**（§三十五）：相同 `(source, query, time_range, hash)` 视为同一证据。

### Evidence Plane 验收条件

- [ ] Evidence 字段完整（id/source/query/timestamp/result/hash/confidence/provenance）
- [ ] 不写/不读 VM/VLogs/MySQL 主数据（仅索引）
- [ ] LLM 推断与 live fact 分离标记
- [ ] 相同查询去重命中

## 4. Reasoning Plane（P7.5 + P7.6 + P7.7）

### 架构域

Reasoning Plane 是"理解意图 → 生成计划"的受控推理层。**核心原则：Planner 输出
Plan Proposal，不是 Execution Command。**

### P7.5 Intent Contract

**职责**：规范化用户调查意图。

**Intent（§合同 Intent Contract）**：
```text
Intent {
  intent_id, analysis_purpose
  hypotheses
  evidence_requirements
  scope (tenant/cluster/capability)
}
```

**V9.3_FROZEN 覆盖规则**：目标歧义 → `RESOURCE_AMBIGUOUS`；证据不足 → `unknown` /
`missing_evidence`，**不得强行给根因**。

**创建者限制**：AI Run 只能由**认证用户显式触发**创建（System Principal 不得自动创建
带执行 scope 的 Run）。

### P7.6 Planner

**职责**：Intent → Plan Proposal。Planner 是**唯一调查控制器**。

**Plan（§四十一）**：
```text
Plan {
  plan_id, intent_id
  steps
  required_tools
  required_evidence
  approval_requirement
  risk_level                // 计划整体风险等级
  requires_human_approval   // 强制 true，阻断 Planner→Executor 隐式直连
}
```

**`requires_human_approval`（强制）**：所有 Plan 必须 `requires_human_approval=true`。
显式阻断任何"Planner → Executor"隐式连接——Plan 仅是提案，执行权只能来自人工批准后的
RunInvocation。

**硬预算（§四十一）**：必须严格执行预算（步骤数/时间/工具调用上限）。超预算 → 终止并
报告 `BUDGET_EXCEEDED`，不强行收敛。

**边界**：**Planner → Executor 禁止直连**。Plan 产出后必须经人工 approval 才能进入
RunInvocation。

**关键约束**：
- 不得存在第二套 Agent 主图（Planner 是唯一调查控制器）
- 证据不足 → `missing_evidence`，不臆测根因
- 目标歧义 → `RESOURCE_AMBIGUOUS`，不猜测

### P7.7 Structured State

**职责**：Agent 调查过程的结构化状态。

**Structured State**：
```text
State {
  state_id, phase
  findings
  hypotheses
  evidence_refs
  confidence
}
```

**边界**：Structured State 记录调查进度，**不包含执行指令**；状态更新不影响外部资源。

**状态机**：
```text
IntentCreated
   ↓
EvidenceCollected
   ↓
PlanGenerated
   ↓
AwaitingApproval      ← Phase7 初期边界（到此为止）
   ↓
Approved              ← 后续阶段
   ↓
Executed              ← 后续阶段
```

**Phase7 范围**：Structured State 只推进到 `AwaitingApproval`；`Approved`/`Executed` 属于
后续阶段（本规划不实现执行状态）。

### Reasoning Plane 数据流

```text
User Intent
   ↓
Intent Contract（规范化 + scope 校验）
   ↓
Planner（生成 Plan Proposal + budget 校验）
   ↓
Human Approval
   ↓
RunInvocation（进入 Agent lifecycle）
```

### Reasoning Plane 验收条件

- [ ] Planner 输出 Plan Proposal，不含执行命令
- [ ] 硬预算严格执行（超限终止，报告 BUDGET_EXCEEDED）
- [ ] 目标歧义 → RESOURCE_AMBIGUOUS；证据不足 → missing_evidence
- [ ] Plan 不经人工 approval 不得进入 RunInvocation
- [ ] 无第二套 Agent 主图

## 5. Agent Runtime Boundary（P7.8 + Agent lifecycle）

### 架构域

Agent Runtime 建立 **Agent contract / context schema / lifecycle**，**不建设自动修复/
自动变更/自动 kubectl**。

### P7.8 Manual Trigger Boundary

**Agent 生命周期**：
```text
Created（用户显式触发）
   ↓
Investigating（调用已注册只读 Tool）
   ↓
Reported（产出 Suggestion/Evidence）
   ↓
（无自动执行——用户决定是否批准变更）
```

**约束**：
- Agent **只能调用已注册只读 Tool**（R0/R1 自动 + audit；R2+ 需 approval）
- Agent **不能**自动触发变更、不能自动 kubectl、不能绕过 approval
- RunInvocation / RunControl / TrustedRequestContext 三 Context 分离（不合并）

**System Principal 禁止项**：
```text
System Principal:
  Allowed:   collect evidence / refresh state / health check
  Forbidden: create RunInvocation / create execution scope / approve plan
```

**三身份模型冻结**（Phase7 不得合并）：
```text
User Identity   → Intent（用户意图）
Service Identity → Tool access（服务工具访问）
Run Identity    → Execution context（运行执行上下文）
```
避免把 `JWT=user` 错误扩展为 `JWT=execution permission`。

### Agent Runtime 验收条件

- [ ] Agent 只能通过已注册只读 Tool 查询
- [ ] 无自动变更 / 自动修复 / 自动 kubectl 路径
- [ ] R2+ 变更必须人工 approval
- [ ] 三 Context（RunInvocation/RunControl/TrustedRequestContext）分离

## 6. Integration & Security Boundary（P7.9 + P7.10）

### 架构域

Integration & Security 层定义数据源映射与横切安全契约。

### P7.9 Data Source Mapping

已注册数据源 → capability → Tool 映射（保持单 SoT）：

```text
MySQL        → Authorization SoT（capability 鉴权 / identity 解析）
VM           → observability.metrics.read → Tool: query_metrics
VLogs        → observability.logs.read    → Tool: query_logs
Query API    → AI Runtime data owner（统一查询入口）
```

**约束**：P7.9 明确平台自身 / 外部 source 使用**相同 ToolResult 状态**与相同证据链。

### P7.10 Security Contract

横切所有 Phase7 域：

- **鉴权**：所有 Agent 查询经 TrustedRequestContext V2 + capability gate
- **scope 收敛**：tenant/cluster 隔离（G6-C 语义复用）
- **审计**：所有 Tool 调用 / Evidence 生成 / Plan 产出留痕（§ audit）
- **禁自动扩大 scope**：Agent 不得要求比 Run 更高的 scope
- **关键错误不降级**：permission_denied/unavailable 不得伪装为 no_data/healthy

### Security 验收条件

- [ ] 所有查询经 TrustedRequestContext V2 + capability gate
- [ ] tenant/cluster 隔离验证通过（复用 G6-C）
- [ ] 无 scope 自动扩大路径
- [ ] 关键错误不降级
