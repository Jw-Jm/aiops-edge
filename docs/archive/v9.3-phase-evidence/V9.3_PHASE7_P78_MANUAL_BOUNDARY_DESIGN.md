## 1. P7.8 Contract

### 核心原则

**AI 调查入口统一收敛为人工显式触发**（P7.8）。Alert/Event/Change 只能作为页面上下文、
预填 scope/time/resource/symptom 和 Evidence 查询起点，**不能自行创建 Run**。

### 固定流程（P7.8）

```text
Alert/Event/Change exists
→ no AI Run automatically created
→ no Planner/Agent/LLM/K8sGPT automatically invoked

Authenticated user explicitly invokes AI analysis
→ realtime authorization
→ RunInvocation
→ Intent
→ Planner
```

### 自动继续规则（P7.8 明确）

同一个用户手动发起的 Run 内，Planner/Agent 可按 DAG **自动继续执行**（不要求每个 Agent/
每次 LLM 子调用再次人工点击）。但：
- Run 完成/取消/失败后，后台**不得自动创建新 AI Run**
- **不得新增**独立 Detection Engine 或告警自动 Agent 图

---

## 2. Trigger Model

### 允许触发

- ✅ 认证用户显式调用（"交给 AI 调查"按钮 / 命令）
- ✅ 用户手动发起的 Run 内，Planner/Agent 按 DAG 自动继续

### 禁止触发

- ❌ Alert/Event/Change 到达自动创建 Run
- ❌ 页面加载/告警到达自动调用 AI
- ❌ Run 结束后后台自动新建 Run
- ❌ 独立 Detection Engine / 告警自动 Agent 图

---

## 3. System Principal 边界

```text
System Principal:
  Allowed:   collect evidence / refresh state / health check
  Forbidden: create RunInvocation / create execution scope / approve plan
```

（v0.2 规划第 5 章）

---

## 4. 三身份模型

```text
User Identity   → Intent（用户意图，触发调查）
Service Identity → Tool access（工具访问）
Run Identity    → Execution context（运行执行上下文）
```

JWT(user) ≠ execution permission。

---

## 5. Test Plan（P7.8）

### T1 无自动 Run

- [ ] Alert 到达 → 不创建 Run
- [ ] Event 到达 → 不创建 Run
- [ ] 页面加载 → 不触发 AI

### T2 人工触发

- [ ] 认证用户显式触发 → RunInvocation
- [ ] 实时鉴权（realtime authorization）通过
- [ ] Run 内 DAG 自动继续（无需每次人工点击）

### T3 Run 生命周期

- [ ] Run 完成/取消/失败后不自动新建 Run
- [ ] 无独立 Detection Engine / 告警自动 Agent 图

### T4 System Principal

- [ ] System Principal 不能创建 RunInvocation / execution scope / approve plan
