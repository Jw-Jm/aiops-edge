## 2. Code Map

```text
orchestrator (Planner/Agent)
    |
    |  InternalQueryClient.query(tool_id, operation, tenant_id, cluster_id, params, context_ref)
    |    ├─ Gate1 _resolve_tool(): Registry active ∧ 非执行类(execution_state!=disabled)
    |    ├─ Gate2 capability 来源: tool.capability（ToolDefinition，非调用方传入）
    |    ├─ Gate3 OPERATION_ROUTES[operation] → 固定 /internal/v1/query/<op>; tool.capability==required
    |    ├─ Gate4 _build_body(): 白名单字段(service/services/query/since/minutes/hours/...); 禁 sql/promql
    |    ├─ issuer.build_claims(): 唯一 request_id/session_id/nonce + short TTL(30s)
    |    ├─ _default_http: sign → X-Internal-Token + X-Trusted-Request-Context → POST
    |    └─ _normalize(): 403→permission_denied, 503→unavailable, 200+NO_DATA→no_data(合法)
    |
    v
query-api /internal/v1/query/*  (8 endpoints, routeCapability 固定映射)
    +--> VictoriaMetrics / VictoriaLogs / (repos)
```

- `OPERATION_ROUTES`：8 个 operation → (endpoint, required_capability)，对齐 query-api `routeCapability`。
- `TrustedContextIssuer.build_claims()`：capability 必须 ∈ `KNOWN_CAPABILITIES`（来自 Tool Registry）。
- `TrustedContextIssuer.issue()`：复用 `trusted_context.sign_trusted_request_context_v2`（EdDSA，不新建体系）。
- `_default_http`：复用 `internal_query._load_private_key` + `_validate_query_api_url`，URL 恒为 `QUERY_API_URL + /internal/v1/query/*`。

## 4. TrustedContext 签发验证

- `issuer.issue()` 产出 token 可被 `verify_trusted_request_context_v2`（同 trust root 公钥 + ReplayCache）验签通过。
- claims 含 `context_type=trusted_request / issuer=ai-orchestrator / audience=ai-apm-query-go / tenant_id / scope_kind=cluster / cluster_id / capability`。
- 每次调用 `request_id / session_id / nonce` 均唯一（uuid4）；TTL 严格 30s（`expires_at - issued_at == timedelta(30)`）。
- 复用 `fQmL5...` trust root：不 rotate、不新建签发体系、不修改 verifier/issuer/audience。

## 5. Scope isolation 测试（T3）

- tenant_id/cluster_id 从调用参数流入 signed context claims（`scope_kind=cluster`）。
- `query_logs.v1`(capability=logs.read) + operation=metrics → DENIED（Tool 能力与端点所需不一致）。
- `query_metrics.v1` + metrics → 允许。

## 6. Replay 防护测试（T4）

- 同一 token 二次验证 → `CONTEXT_REPLAYED`（唯一 nonce）。
- 过期 context（issued_at/expires_at 提前 5min）→ `EXPIRED_CONTEXT` 拒绝。
- 每次签发唯一 session/nonce/request_id → 同请求重放被拒绝。

## 7. permission_denied ≠ no_data 验证（T5）

| HTTP | body | client 语义 | 证明 |
|------|------|------------|------|
| 200 | `{"error":"NO_DATA"}` | `QueryResult(http_status=200, body)` 合法空结果，不抛 | 不降级 |
| 403 | `TENANT_ACCESS_DENIED` | `InternalQueryError(kind=permission_denied, http_status=403)` | 不降级为 no_data |
| 503 | `BACKEND_UNAVAILABLE` | `InternalQueryError(kind=unavailable, http_status=503)` | 不降级为 healthy |

- 生产路径 `_default_http` 保留 403（HTTPError → `(403, body)`），`_normalize` 据此区分 → 生产链路同样不降级。

---

## 8. 无旁路访问证明（T2 + 生产路径）

- `InternalQueryClient` 无任何 direct DB/CH/VM/VLogs/K8s 连接路径；唯一 I/O 点是注入的 `http` transport。
- 默认 `_default_http` URL 恒为 `QUERY_API_URL + /internal/v1/query/<op>`（8 个操作全部断言），非 `/internal/v1/query/*` 端点不可达（`_validate_query_api_url` 校验 host/port/path）。
- 未知 operation（如 `db_direct`）→ `invalid_context` 拒绝。
- params 含 `sql`/`promql` → `invalid_context` 拒绝（禁止 backend query language）。
