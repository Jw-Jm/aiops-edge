## 1. P7.2 Contract

### 职责

- **唯一事实路径**：orchestrator（Planner/Agent）**只能**通过 `/internal/v1/query/*` 获取
  事实（P7.2 + §72）。禁止 direct DB/ClickHouse/VM/VLogs/K8s（§66-B）。
- **受控签发**：每次调用按 `tenant/cluster/capability` 签发 TrustedRequestContext V2。
- **能力承载**：InternalQueryClient 是 Tool Plane 的底层调用通道，供 P7.1 已注册 Tool 使用。

### 边界

| 允许 | 禁止 |
|------|------|
| 经 TrustedRequestContext V2 调 `/internal/v1/query/*` | direct DB/CH/VM/VLogs/K8s 访问 |
| 按已注册 Tool 的 capability 签发 context | 扩展/伪造 capability |
| 复用现有 `fQmL5...` trust root（不 rotate） | 新建签发体系 / 新 token 类型 |
| tenant/cluster 隔离 | 跨 tenant/cluster scope 扩大 |

### 继承能力（现有实现，非新设计）

- query-api 已有 `/internal/v1/query/logs` 与 `/internal/v1/query/metrics`（B2.0 已验证）
- `authorizeInternalQuery`：X-Internal-Token + TrustedRequestContext V2 + capability + scope
- verifier：`TRUSTED_CONTEXT_PUBLIC_KEYS=fQmL5...`，issuer `ai-orchestrator`，audience `ai-apm-query-go`
- P7.2 是 **orchestrator 侧客户端**封装，复用上述服务端能力，不重建

## 2. InternalQueryClient Schema

### 客户端接口

```text
InternalQueryClient {
  query(QueryRequest) -> QueryResult
}

QueryRequest {
  tool_id         string    // 已注册 Tool（P7.1）
  operation       enum      // logs | metrics | traces | alerts | topology | k8s
  tenant_id       string    // canonical tenant（7ed01afc-...）
  cluster_id      string    // canonical cluster（91771a6e-...）
  capability      string    // 请求 capability（映射 §31）
  context_ref     string    // 调用上下文引用（评审建议 2，可追踪 Tool→QueryRequest→TrustedContext→audit）
  params          object    // Tool 参数（结构化工参，≠ backend query language）
}
```

### 关键约束

- `tool_id` 必须是 Registry 中 `active` 的 Tool（P7.1 gate 前置）
- **禁止传 backend query language**（评审建议 2）：
  ```text
  禁止: {"sql":"select ..."} / {"promql":"..."}
  允许: {"tool_id":"query_logs","parameters":{"service_name":"checkout","time_range":"1h"}}
  ```
  **Tool Parameter ≠ Backend Query Language**
- `context_ref` 使调用链可追踪：`Tool → QueryRequest → TrustedRequestContext → query-api audit`

QueryResult {
  http_status     int
  body            bytes
  normalized      ToolResult  // 由 P7.3 归一化
}
```

### 关键约束

- `tool_id` 必须是 Registry 中 `active` 的 Tool（P7.1 gate 前置）
- 不得直接传原始 SQL / PromQL 到非授权端点
- 每次调用走 `/internal/v1/query/*`，**禁止旁路**到 DB/VM/VLogs

## 3. TrustedContextIssuer Schema

### 职责

- 为每次 InternalQueryClient 调用**按 tenant/cluster/capability 签发** TrustedRequestContext V2。
- 使用**现有 private key**（`/tmp/p65_sign_ctx.py` 的 `hdPBJ...`，与 `fQmL5...` 配对），**不 rotate**。

### 签发 payload（§66-B V2 字段）

```text
TrustedRequestContext V2 {
  version, context_type: trusted_request
  issuer: ai-orchestrator
  audience: ai-apm-query-go
  request_id: uuid          // 唯一
  principal_type, principal_id
  session_id: uuid          // 唯一（防 replay）
  tenant_id: <请求 tenant>
  issued_at, expires_at     // 短时效（如 30s）
  nonce: uuid               // 唯一（防 replay）
  run_id, scope_kind: cluster, cluster_id: <请求 cluster>
  capability: <请求 capability>   // 精确到 Tool 所需 capability
  source: planner
}
```

### 签名与验签

```text
EdDSA (Ed25519)
header: {"alg":"EdDSA","kid":sha256(publicKey)base64url,"typ":"AIOPS-CONTEXT"}
payload: above V2 fields
signature: Ed25519(privateKey, "header.payload")
```

query-api 用 `fQmL5...` 验签（B2.0/G6-B 已验证闭环）。

### 关键约束

- **每次调用唯一 session/nonce/request_id**（防 replay，B2.0 已验证 CONTEXT_REPLAYED 机制）
- 签发 scope = 当前 Run 的 scope，**不自动扩大**
- capability 精确到当前 Tool 所需（logs.read 不能签成 metrics.write）
- **时间窗口**（评审建议 1）：`issued_at`/`expires_at` 短时效（如 30s）。nonce 防"同请求重放"，时间窗口防"长有效 token 盗用"。过期 context 拒绝。
- **capability 来源约束**（评审建议 4，必须）：capability **只能来自 Tool Registry**（映射 §31），经 `InternalQueryClient → TrustedContextIssuer` 单向传递。**禁止 LLM/Agent 生成或篡改 capability 字符串**（Agent 不生成权限）。

```text
Capability Source:
Tool Registry → InternalQueryClient → TrustedContextIssuer
（禁止 LLM → capability string）
```

## 4. Security Boundary

- **禁旁路**：orchestrator 任何组件不得直连 DB/CH/VM/VLogs/K8s 获取事实（§66-B）
- **scope 收敛**：签发 context 的 tenant/cluster/capability 严格来自当前 Run，不扩大
- **三身份分离**：User（Intent）→ Service（Tool access）→ Run（Execution context）
- **replay 防护**：唯一 session/nonce/request_id；复用 → CONTEXT_REPLAYED 拒绝
- **鉴权失败语义**：`permission_denied` 不降级为 `no_data`；`unavailable` 不降级为 `healthy`

## 5. Test Plan（P7.2）

### T1 正确签发与查询

- [ ] 合法 tenant/cluster/capability → 签发成功，`/internal/v1/query/logs` 返回 HTTP 200
- [ ] 每次调用 session/nonce/request_id 唯一
- [ ] 验签通过（query-api 用 `fQmL5...`）

### T2 禁旁路

- [ ] InternalQueryClient 调用 URL 恒为 `/internal/v1/query/*`
- [ ] 无 direct DB/VM/VLogs 连接路径（静态检查 + 测试）
- [ ] 非 `/internal/v1/query/*` 端点不可达

### T3 Scope 收敛

- [ ] tenant A 的 context 无法读 tenant B 数据 → NO_DATA
- [ ] cluster A 的 context 无法读 cluster B → NO_DATA
- [ ] logs.read 无法调 metrics 端点 → 403 TENANT_ACCESS_DENIED

### T4 Replay 防护

- [ ] 复用 session/nonce → CONTEXT_REPLAYED（401）
- [ ] 过期 context → 拒绝

### T5 安全语义

- [ ] `permission_denied` 不降级为 `no_data`
- [ ] `unavailable`（backend 不可达）不降级为 `healthy`
- [ ] 未注册 Tool 的 capability → 拒绝

### T6 Tool-Capability Binding Integrity（评审建议 3）

- [ ] `tool_id=query_logs` + `capability=metrics.write` → **DENIED**（Tool 与 capability 不一致）
- [ ] `tool_id=query_metrics` + `capability=observability.metrics.read` → 允许
- [ ] capability 非法/未在 Registry 注册 → 拒绝
- [ ] LLM 试图注入 capability 字符串 → 拒绝（capability 仅来自 Tool Registry）
- [ ] `Tool → Capability → TrustedContext` 三者一致才放行
