## 1. Execution Phase Contract

### 职责

- 把 `ExecutionContract(active) + ExecutionIdentity + PolicyDecision(ALLOW) + ExecutionPreview(approved)`
  转化为真实 Adapter 的受限执行（K8s/OpenStack/VM）。
- 以 5 Schema v1 为不可变契约，**不新建身份/凭据/查询体系**。
- 纳入评审非阻塞项：R1（Approval Signature）、R2（资源版本绑定）、R3（真实 SoT 接入）。

### 边界

| 允许 | 禁止 |
|------|------|
| 设计真实 Adapter 接入（K8s/OpenStack/VM） | 连接真实系统（本阶段仅设计） |
| 设计 Credential Broker 委托 | Agent 持有长期凭据 / 明文 Secret |
| 设计 Ed25519 Approval Signature（R1） | 无 signature 的 contract 执行 |
| 设计资源版本绑定（R2） | Preview 后执行对象漂移 |
| 设计 Rollback 流程 | Agent 自动 rollback |

### 非目标（本 Execution Phase 设计不做）

- ❌ 不实现真实 Adapter / 不连 K8s/OpenStack
- ❌ 不改 5 Schema v1（不可变契约）
- ❌ 不改 V9.3 Authorization Boundary

## EX.1 Ed25519 Approval Signature（R1 纳入）

### 背景

当前 `contract_hash`（SHA256）是 Integrity Check：证明"内容没变"，但不证明"谁批准"。
R1 升级为 **Authorization Signature**：证明"谁批准"。

### 设计

```text
ApprovalSignature {
  signer          user_id      // 审批人（Human）
  algorithm       Ed25519
  payload         SHA256(contract 关键字段)   // contract_id + actions + resources + expire_time
  signature       Ed25519_priv(signer, payload)
  signed_at       time
}
```

### 流程

```text
PlanProposal(awaiting_approval)
   ↓ Human approval（用户用私钥签名 payload）
ApprovalSignature 附加到 ExecutionContract
   ↓ 存储 contract.signature = signature
   ↓ 执行时
Adapter 校验: verify_contract_scope + verify_approval_signature
   （公钥验签，确认 signer=approved_by）
```

### 约束

- `signer` 必须 == `contract.approved_by`（谁批准谁签名）。
- 公钥来自用户身份（不引入新授权体系；复用 V9.2 身份公钥体系）。
- 验签失败 → 拒绝执行（无 signature 不执行）。
- `contract_hash` 保留为防篡改（Integrity）；`signature` 为审批认证（Authorization）。

### Test Plan（EX.1）

- T1 有效 signer 签名 → 验签通过
- T2 signer ≠ approved_by → 拒绝
- T3 篡改 payload → 验签失败（拒绝）
- T4 无 signature → 拒绝执行

## EX.2 Credential Broker（凭据委托）

### 背景

真实执行需要真实系统凭据，但 **Agent/Planner/Evidence 绝不接触凭据内容**（V9.3 红线）。

### 设计

```text
credential_ref（contract/identity 只存引用）
   ↓
Credential Broker
   ↓
Short-lived Credential（一次性，随 contract expire_time 过期）
   ↓
Execution Adapter（仅执行期持有，用后即弃）
```

### Broker 接口

```text
interface CredentialBroker v1 {
  delegate(credential_ref, execution_identity) -> ShortLivedCredential
  revoke(credential_ref)            // 撤销，阻断
  credential_lifetime(contract)     // 随 contract expire_time
}
```

### 约束

- Broker 是唯一能接触真实凭据的组件；Adapter 仅执行期通过 Broker 获得 short-lived 凭据。
- short-lived 凭据：随 contract expire_time 过期；contract revoked → Broker revoke。
- Agent/Planner/Evidence **永不接触凭据内容**（Evidence 不存 Secret）。
- 凭据不落日志 / 不落 Evidence / 不落 contract。

### Test Plan（EX.2）

- T1 Broker 返回 short-lived 凭据（非长期）
- T2 凭据随 contract expire → 失效
- T3 contract revoked → Broker revoke → 凭据失效
- T4 Agent/Planner/Evidence 无凭据访问路径（静态检查）

## EX.3 真实 Adapter 接入（K8s/OpenStack/VM）

### 背景

所有真实 Adapter 必须实现冻结的 **Adapter Interface v1**（execute/dry_run/verify_contract_scope），不各自扩展。

### 设计（K8s Adapter 示例）

```text
K8sAdapter implements ExecutionAdapter v1 {
  adapter_id = "k8s-adapter"

  execute(request, contract):
    verify_contract_scope(request, contract)   // fail-closed
    verify_approval_signature(contract)        // EX.1
    credential = broker.delegate(...)          // EX.2
    before_state = read(kubectl get ...)       // 采集执行前状态
    result = run(kubectl <action>)             // 受限动作（白名单内）
    after_state = read(...)                    // 采集执行后状态
    return AdapterResult(before_state, after_state, trace_id, ...)

  dry_run(request, contract):
    return preview 语义（无副作用）

  verify_contract_scope(request, contract):
    action ∈ allowed_actions
    namespace ∈ allowed_resources
    contract active + 未过期
}
```

### 约束

- Adapter 只执行 `contract.allowed_actions` 白名单内动作（缺省拒绝）。
- 每个 Adapter 记录 `before_state/after_state`（可靠 RCA / Rollback 依据）。
- Adapter 不持有长期凭据（经 Broker 一次性获取）。
- OpenStack/VM Adapter 同构（OpenStack CLI/SDK、VM API），共享 v1 接口。

### Test Plan（EX.3）

- T1 Adapter 校验 action/target 白名单（fail-closed）
- T2 dry_run 无副作用
- T3 before/after state 采集正确（回滚依据）
- T4 无凭据访问路径（经 Broker）

## EX.4 Rollback 机制

### 背景

真实执行可能失败/需要回滚。Rollback 责任边界已冻结：Agent 建议 / Human 批准 / Policy 检查 / Adapter 执行。**禁 Agent 自动 rollback**。

### 设计

```text
RollbackRequest:
  contract.rollback_policy    // 触发条件/回滚动作
  before_state                // EX.3 采集（回滚目标）
  approved_by                 // 必须 Human 批准
  → Policy evaluate（回滚是否允许/超限）
  → Adapter 执行回滚（到 before_state）
```

### 约束

- Rollback 是执行动作，必须 Human 批准 + contract（不能 Agent 自动）。
- Rollback 目标 = `before_state`（Adapter 采集的执行前状态）。
- 无 before_state → 拒绝 rollback（无法确定回滚目标）。
- rollback 受 Policy 检查（次数/影响限制）。

### Test Plan（EX.4）

- T1 无 Human 批准 → 拒绝 rollback
- T2 无 before_state → 拒绝 rollback
- T3 rollback 经 Policy 检查
- T4 Agent 不能自动 rollback

## EX.5 Preview 资源版本绑定（R2 纳入）

### 背景

Preview 后资源可能已变化，导致"执行对象漂移"（Preview 时的目标 ≠ 执行时的目标）。

### 设计

```text
ExecutionPreview（增强，R2）:
  + resource_version   // 目标资源当前版本（如 pod version=v1）
  + cluster_id         // 执行集群（canonical）
  + namespace          // 执行命名空间
```

执行时 Adapter 校验：当前资源版本 == Preview 时记录的 `resource_version`；不一致 → 拒绝执行（对象已漂移）。

### 约束

- `resource_version` 防漂移：执行前校验当前版本 == Preview 记录。
- `cluster_id`/`namespace` 绑定：执行必须在 Preview 记录的目标内。
- 版本不匹配 → 拒绝（避免对已变化的资源执行）。

### Test Plan（EX.5）

- T1 当前版本 ≠ Preview.resource_version → 拒绝执行
- T2 cluster/namespace 与 Preview 不符 → 拒绝
- T3 版本一致 → 允许执行

## EX.6 Policy 真实 SoT 接入（R3）

### 背景

P8.4 Policy Context 来源冻结（authorization_sot 等）；R3 接入真实 MySQL SoT。

### 设计

```text
Policy Context（真实接入）:
  authorization_sot   ← MySQL（V9.3 Authorization SoT）
  cluster_state       ← 真实集群状态查询（经 query-api 只读，不旁路）
  execution_history   ← 执行记录（Execution Phase 持久化）
  current_time        ← 系统时钟
```

### 约束

- `authorization_sot` 从 MySQL SoT 读取（V9.3 已冻结）。
- `cluster_state` 经 query-api 只读（禁止 orchestrator 直连集群，P7.2 唯一事实路径延续）。
- Policy Context 仍禁 LLM/Agent/Frontend（P8.4 冻结延续）。

### Test Plan（EX.6）

- T1 authorization_sot 从 MySQL SoT 读取
- T2 cluster_state 经 query-api（无旁路）
- T3 LLM/Agent/Frontend context 仍拒绝

## 统一真实执行路径（Execution Phase 确立）

```text
ExecutionContract(active, signed)      // EX.1 签名
   ↓ Policy evaluate → ALLOW           // EX.6 真实 SoT
   ↓ ExecutionPreview approved         // EX.5 资源版本绑定
   ↓ Credential Broker → short-lived   // EX.2
   ↓ ExecutionAdapter.execute          // EX.3（真实系统）
   ↓ before/after state 采集
   ↓ success → executed | 失败 → Rollback（EX.4，Human 批准）
```

## 安全分层

```text
静态（Phase7）: SecurityGate（能不能）
动态（Phase8）: Runtime Policy（什么条件下可以）
一次性（Phase8）: ExecutionContract + Credential Delegation
审批（EX.1）: Ed25519 Approval Signature（谁批准）
执行（EX.3）: 真实 Adapter（只做批准的事）
回滚（EX.4）: Human 批准，到 before_state
```

## 红线保持（F1-F5 + Execution Phase）

```text
F1 LLM 非权威：signature 由 Human 签发；Policy/credential 禁 LLM
F2 三+一身份分离：approved_by ≠ requested_by ≠ executed_by（EX.1 signer=approved_by）
F3 Evidence 边界：Credential/Secret 绝不落 Evidence
F4 Planner 边界：Planner 不直连执行；真实执行经 Contract+Adapter
F5 End State：Execution Phase 设计阶段不触发真实执行
新增：无 Approval Signature 不执行；凭据经 Broker；Rollback 须 Human 批准；资源版本防漂移
```
