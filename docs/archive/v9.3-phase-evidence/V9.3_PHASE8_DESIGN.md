# P8.1 Execution Contract Design

## 1.1 Contract

### 职责

- 把 `PlanProposal`（Phase7 停在 `awaiting_approval`）经**人工 approval** → 生成**一次性 ExecutionContract**。
- **Approval 不是授权执行，而是生成一次性执行许可证**（类比 K8s Admission Controller + Cloud IAM Temporary Credential）。

### 边界

| 允许 | 禁止 |
|------|------|
| 经人工 approval 生成一次性 ExecutionContract | 无 contract 直接执行 |
| 绑定 allowed_tools/allowed_resources/allowed_actions/max_scope | contract 复用 / 延长 / 扩大 |
| 绑定 approved_by/requested_by/executed_by | approval 自动授权执行 |
| 短时效 expire_time + rollback_policy | Agent/Planner 生成或篡改 contract |
| 绑定 credential_ref（经 Broker 委托） | Agent 直接持有长期凭据 |

### 非目标

- ❌ 不实现真实执行 / 不连 K8s/OpenStack / 不写 SQL/SSH
- ❌ 不做 Runtime Policy（P8.4）/ Adapter（P8.3）/ Simulation（P8.5）——仅定义 contract 语义

## 1.2 ExecutionContract Schema

```text
ExecutionContract {
  contract_id        string
  plan_id / intent_id / run_id     // 关联 P7.6/P7.5/P7.7
  approved_by / approved_at        // 审批人（Human）
  requested_by       string         // 请求发起（Agent/User）
  executed_by        string         // 执行身份（Execution Identity，P8.2）
  allowed_tools      []string       // 已注册 Tool 白名单（P7.1）
  allowed_resources  []string       // 允许作用资源（namespace/service/pod）
  allowed_actions    []string       // 允许动作白名单（缺省拒绝，非黑名单）
  max_scope          enum           // cluster|namespace|resource（不自动扩大）
  expire_time        time           // 一次性短时效（如 5min）
  rollback_policy    object         // {rollback_action, rollback_timeout, requires_approval}
  contract_hash      string         // 不可变指纹（评审补充：防运行期篡改）
  signature          string         // 审批签名（created_version + hash）
  created_version    string         // 生成时的 schema 版本
  status             enum           // draft|approved|active|executing|executed|expired|revoked
}
```

### 关键约束

- `allowed_actions` 是**白名单**（缺省拒绝）。
- `max_scope` 严格来自当前 Run，**不自动扩大**（P7.2 scope 收敛延续）。
- **contract_hash 不可变**（评审补充）：`SHA256(contract_id + actions + resources + expire_time)`；Adapter 执行时校验 `received hash == approved hash`，否则拒绝（防运行期篡改）。
- **execution_lock 状态机**（评审补充，防并发重复执行）：
  ```text
  active → acquire_lock → executing → executed
  ```
  同一 contract 只有一个 Adapter 能 acquire_lock；防 retry + network timeout + duplicate execute 导致重复操作。
- 状态机单向：`draft → approved → active → executing → (expired|revoked|executed)`；`revoked` 不可逆回 active。
- 一次性：执行后 `executed`，过期 `expired`，不可复用/续期。

### Run 模型关联（评审缺口 1 补齐）

```text
ExecutionContract
   │
   ↓
ai_actions（动作级：同一 Run 的多个 Action 各自 contract）
   │
   ↓
ai_runs（Run 级：Root Cause + 多个 Action）
```

一个 Run 的多个 Action（Action A/B）各自独立 ExecutionContract，经 `run_id` 关联回同一 `ai_runs`，区分"哪个 Action 被批准/执行"。

## 1.3 Security Boundary

```text
PlanProposal(awaiting_approval)
   ↓ ONLY via user approval
ExecutionContract(active)
   ↓ ONLY with contract + credential
Execution Adapter（P8.3）
```

- **不可绕过**：无 contract 不能执行；Agent/Planner 不能生成或篡改 contract。
- **Credential Delegation**：`credential_ref → Credential Broker → Short-lived Credential → Adapter`；Agent 不持长期凭据、Planner 不接触凭据、Evidence 不存 Secret。
- **Dry-run 前置**：真实执行前必须 `ExecutionPreview`（P8.5），人工确认后才允许 active。
- **Runtime Policy 预留**：contract 预留 policy 字段，P8.4 实现 Execution Policy Engine。

## 1.4 Test Plan（T1-T8）

- T1 不可绕过：无 contract 拒绝；draft/expired/revoked 拒绝；仅 active+有效期内可执行
- T2 一次性：executed 不可复用；expired 不可续；revoked 不可逆
- T3 Scope 收敛：白名单外 action/resource 拒绝；max_scope 扩大拒绝
- T4 Approval ≠ 授权执行：approval 仅生成 contract，不触发执行；无 contract 的执行尝试拒绝
- T5 Credential Delegation：Agent/Planner 不接触长期凭据；Evidence 不存 Secret
- T6 Dry-run：真实执行前必须 ExecutionPreview；preview 未确认不进入 active
- T7 **hash 完整性**（评审补充）：篡改 actions/resources/expire_time → contract_hash 不匹配 → Adapter 拒绝
- T8 **execution_lock**（评审补充）：同 contract 二次 acquire_lock → 拒绝（防并发重复执行）；executing 时不可再执行

## 1.5 验收条件

- [ ] PlanProposal → 人工 approval → 一次性 ExecutionContract（不可绕过）
- [ ] Approval 不是授权执行，而是生成一次性执行许可证
- [ ] allowed_tools/resources/actions/max_scope 严格白名单 + scope 不扩大
- [ ] expire_time 短时效一次性；revoked 可阻断
- [ ] contract_hash 不可变 + signature（执行时校验，防篡改）
- [ ] execution_lock 防并发重复执行
- [ ] ExecutionContract ↔ Run 关联（ai_actions/ai_runs，区分多 Action）
- [ ] 身份分离（approved_by/requested_by/executed_by）
- [ ] 所有测试（T1-T8）通过

# P8.2 Execution Identity Design

## 2.1 Contract

### 职责

- 建立**第四层身份**（Execution Identity），回答审计链三问：

```text
Who approved?   → approved_by（Human）
Who requested?  → requested_by（Agent/User）
Who executed?   → executed_by（Execution Identity）
```

### 身份分层（Phase7 三身份 + Phase8 第四层）

```text
Human Identity          → Intent（用户意图）
Agent Identity          → Proposal（Agent 提议）
Service Identity        → Tool access（工具访问）
Execution Identity      → Approved Action（获批的一次性执行身份）
```

### 边界

| 允许 | 禁止 |
|------|------|
| 建立 approved_by/requested_by/executed_by 分离 | 单一身份贯穿审批→执行（审计链断裂） |
| executed_by 绑定一次性 contract + 短时效 | executed_by 复用为长期执行身份 |
| 记录完整审计链 | Agent 自行选择 executed_by |
| executed_by 不含长期凭据（经 Broker） | 身份声明 ≠ 执行权限（F2 延续） |

### 非目标

- ❌ 不创建真实用户/凭据系统 / 不改 P7.8 三身份
- ❌ 不实现 Adapter（P8.3）

## 2.2 ExecutionIdentity Schema

```text
ExecutionIdentity {
  identity_id        string         // execution_identity_id（UUID，评审补充：非裸 string）
  run_id / contract_id              // 关联 P7.7 / P8.1
  executed_by        string         // 执行身份 principal
  identity_type      enum           // user|service|execution
  principal_id       string         // 底层 identity ref
  credential_ref     string         // 凭据委托引用（不持 Secret）
  scope              string         // 绑定 scope（不自动扩大）
  issued_at / expire_time           // 随 contract 一次性过期
  status             enum           // issued|active|expired|revoked
}
```

### 评审补充：executed_by UUID 化 + 独立生命周期

`ExecutionContract.executed_by` 引用 `execution_identity_id`（UUID），而非裸 string。Execution Identity 是**独立实体**（有自己的 issued_at/expire_time/status），支持完整生命周期：

```text
User → Agent → Execution Identity(UUID) → K8s Adapter → Cloud API
```

未来多 Adapter / 多 Cloud 时，每个执行动作有独立可追踪的 execution_identity。

### 审计链（完整可追溯）

```text
approved_by (Human)
   ↓ 关联
requested_by (Agent)  → intent_id/run_id
   ↓ 关联
executed_by (Execution Identity) → contract_id
   ↓
Adapter 执行（P8.3）→ audit 记录（谁批准/谁发起/谁执行 + 时间戳 + 结果）
```

## 2.3 Security Boundary

- **F2 延续**：身份声明 ≠ 执行权限；Execution Identity 只是一次性执行许可身份，不含长期权限。
- executed_by 由系统从 contract 派生，**Agent 不能自选**。
- executed_by 生命周期绑定 contract：contract revoked → executed_by revoked（阻断执行）。
- 审计链强制：每次执行必须能追溯到 approved_by + requested_by + executed_by，否则拒绝。

## 2.4 Test Plan（T1-T5）

- T1 身份分离：approved_by/requested_by/executed_by 三值分离；executed_by ≠ 长期 Service Identity
- T2 审计链：每次执行可追溯；缺任一环拒绝
- T3 一次性+过期：executed_by 随 contract expire；revoked 阻断；不可复用
- T4 Credential 边界：credential_ref 不存 Secret；Agent/Planner 不接触长期凭据；Evidence 不存 Secret
- T5 不可自选：Agent 不能自选 executed_by；身份声明 ≠ 执行权限

## 2.5 验收条件

- [ ] 第四层 Execution Identity 建立，审计链完整
- [ ] executed_by 一次性 + 随 contract 过期/撤销
- [ ] approved_by/requested_by/executed_by 分离
- [ ] Agent 不能自选 executed_by
- [ ] execution_identity_id 用 UUID（独立实体，独立生命周期）
- [ ] Credential Delegation 边界
- [ ] 所有测试（T1-T5）通过

# P8.3 Adapter Boundary Design

## 3.1 Contract

### 职责

- 定义 **Execution Adapter Interface**：`execute(contract, credential, target)`。
- 隔离层：Contract → Adapter 单向；Adapter **不连接真实 K8s/OpenStack**（本阶段只定义接口语义）。

### 边界

| 允许 | 禁止 |
|------|------|
| 定义 execute(contract, credential, target) 接口 | 连接真实 K8s/OpenStack/SSH/SQL |
| Adapter 校验 action ∈ allowed_actions、target ∈ allowed_resources | Adapter 扩展权限/绕过 contract |
| 支持 dry_run（无副作用） | 无 active contract / 无有效 credential 执行 |
| 返回 AdapterResult + rollback_ref | Adapter 保存/泄漏 credential |

### 非目标

- ❌ 不实现真实 adapter（后续阶段）
- ❌ 不连接任何真实系统

## 3.2 Adapter Schema

```text
AdapterRequest {
  contract_id        string   // 必须 active contract（P8.1）
  credential_ref     string   // 委托凭据引用（经 Broker，不持 Secret）
  target             object   // {namespace, resource_type, resource_id}
  action             string   // 动作（restart/scale/...）
  params             object   // 动作参数
  dry_run            bool     // true=无副作用验证
}

AdapterResult {
  status             enum     // success|failed|denied|dry_run
  output             object   // 执行结果
  rollback_ref       string   // 回滚引用（P8.1 rollback_policy）
  executed_at        time
  adapter_id         string   // 评审补充：哪个 Adapter 执行
  target_snapshot    object   // 评审补充：目标状态快照
  before_state       object   // 评审补充：执行前状态（如 replicas=3）
  after_state        object   // 评审补充：执行后状态（如 replicas=5）
  execution_trace_id string   // 评审补充：执行追踪 id（可靠 RCA）
}
```

### 接口（冻结 v1，评审缺口 3 补齐）

```text
execute(request: AdapterRequest) -> AdapterResult
```

**ExecutionAdapter Interface v1**（冻结，避免后续 K8s/OpenStack/VM Adapter 各自设计一套）：

```text
interface ExecutionAdapter v1 {
  execute(request: AdapterRequest) -> AdapterResult
  dry_run(request: AdapterRequest) -> ExecutionPreview      // P8.5 语义
  verify_contract_scope(request) -> bool                    // 二次校验 action/target scope
}
```

- 所有真实 Adapter（K8s/OpenStack/VM）必须实现 v1 接口；`adapter_id` 区分具体实现。
- `before_state`/`after_state`/`target_snapshot` 必须记录（运维恢复 / RCA 依赖）。

### 关键约束

- Adapter 只接受 `active` contract + 有效 credential；否则 `denied`。
- Adapter 校验 `action` ∈ contract.allowed_actions、`target` ∈ contract.allowed_resources；否则 `denied`。
- `dry_run=true` 时无副作用，仅返回 preview 语义（P8.5）。
- Adapter 不持有/不保存 credential（一次使用后失效）。

## 3.3 Security Boundary

- **单向隔离**：Contract → Adapter；Adapter 不能反向影响 contract/审批。
- Adapter 是执行边界的最后一道门：即使 contract 已 active，Adapter 仍二次校验 action/target scope。
- 无 active contract / 无有效 credential → `denied`（fail-closed）。

## 3.4 Test Plan（T1-T6）

- T1 contract 未 active → denied
- T2 action 白名单外 → denied
- T3 target 资源范围外 → denied
- T4 无有效 credential → denied
- T5 dry_run 无副作用（不产生真实执行）
- T6 **审计字段**（评审补充）：success 时 AdapterResult 含 adapter_id/target_snapshot/before_state/after_state/execution_trace_id；缺任一 → 不可作为可靠执行证据

## 3.5 验收条件

- [ ] 定义 execute(contract, credential, target) 接口（不连真实系统）
- [ ] 冻结 ExecutionAdapter Interface v1（execute/dry_run/verify_contract_scope）
- [ ] Adapter 二次校验 action/target scope（fail-closed）
- [ ] 支持 dry_run 无副作用
- [ ] AdapterResult 记录 before_state/after_state/target_snapshot（可靠 RCA）
- [ ] Adapter 不持有/保存 credential
- [ ] 所有测试（T1-T6）通过

# P8.4 Runtime Policy Design

## 4.1 Contract

### 职责

- **Execution Policy Engine**：执行前**动态**检查（Phase7 SecurityGate 是静态，P8.4 是运行时）。

### 检查项（评审建议 5）

| 检查 | 示例 |
|------|------|
| 时间窗口 | 禁止凌晨执行 |
| 资源范围 | 只能 namespace A |
| 动作范围 | 禁止 delete |
| 次数限制 | 1 小时最多 3 次 |
| 影响范围 | pod 数量限制 |

### 边界

| 允许 | 禁止 |
|------|------|
| 执行前动态 evaluate(contract, context) | 静态安全（Phase7）替代运行时策略 |
| PolicyDecision ALLOW/DENY + reason | DENY 降级为 ALLOW |
| 绑定 contract + Run scope | 策略绕过 / 无策略执行 |
| 次数/影响/时间窗口/资源/动作检查 | Agent 修改策略 |

### 非目标

- ❌ 不实现真实执行 / 不连真实系统
- ❌ 不改 Phase7 SecurityGate（静态层保留）

## 4.2 Policy Schema

```text
PolicyRule {
  policy_id        string
  policy_type      enum     // time_window|resource_scope|action_scope|rate_limit|impact_limit
  allowed_values   []string // 允许值（资源/动作/namespace）
  denied_values    []string // 显式禁止值（如 delete）
  limit            int      // 次数/影响上限
  scope            string   // 绑定 scope
}

PolicyDecision {
  decision         enum     // ALLOW|DENY
  reason           string
  policy_id        string
  checked_at       time
}
```

### 接口

```text
evaluate(contract: ExecutionContract, context) -> PolicyDecision
```

### 关键约束

- policy 是**动态**检查：时间窗口/次数/影响在运行时评估，非 contract 静态字段。
- DENY 不可降级为 ALLOW；DENY 理由必须可审计（policy_id + reason）。
- 策略绑定 contract + Run scope，不自动扩大。

### 评审补充（最大风险点）：Policy Context 来源冻结

`evaluate(contract, context)` 的 `context` **必须来自权威数据源**：

```text
Policy Context 来源（冻结）:
  MySQL Authorization SoT    // 鉴权/授权（V9.3 已冻结）
  Cluster State              // 集群真实状态
  Execution History          // 历史执行记录（次数/影响累积）
  Current Time               // 当前时间（时间窗口）

禁止:
  ❌ LLM output
  ❌ Agent suggestion
  ❌ Frontend parameter
```

**原因**：V9.3 已冻结 Authorization SoT = MySQL；Policy 若接受 LLM/Agent/Frontend 输入，则 LLM 可影响执行策略，破坏 F1（LLM 非权威）。

## 4.3 Security Boundary

- Phase7 SecurityGate（静态）→ Phase8 Policy Engine（动态）双层：静态保证"能不能"，动态保证"什么条件下可以"。
- 每条执行必须过 policy；DENY 即阻断（无绕过）。
- 次数/影响限制跨 Run 累积（防批量滥用）。

## 4.4 Test Plan（T1-T7）

- T1 时间窗口外 → DENY
- T2 资源范围外 → DENY
- T3 动作范围外（delete 被禁）→ DENY
- T4 次数超限 → DENY
- T5 影响范围超限 → DENY
- T6 DENY 不降级为 ALLOW
- T7 **Context 来源**（评审补充）：LLM/Agent/Frontend 提供的 context → 拒绝；仅 MySQL SoT/Cluster State/Execution History/Current Time 可作 context

## 4.5 验收条件

- [ ] Execution Policy Engine：执行前动态检查
- [ ] 5 类检查（时间/资源/动作/次数/影响）全实现
- [ ] Policy Context 来源冻结（MySQL SoT + Cluster State + Execution History + Current Time；禁 LLM/Agent/Frontend）
- [ ] DENY 不降级；理由可审计
- [ ] 策略绑定 contract + scope
- [ ] 所有测试（T1-T7）通过

# P8.5 Simulation Design

## 5.1 Contract

### 职责

- **ExecutionPreview**：真实执行前的无副作用验证。
- 输入 `restart pod xxx` → 生成 `ExecutionPreview{target, impact, risk, rollback, actions}` → 人工确认后才真实执行。

### 边界

| 允许 | 禁止 |
|------|------|
| 生成无副作用 ExecutionPreview | preview 触发真实副作用 |
| 评估 impact/risk/rollback/actions | preview 未确认即真实执行 |
| preview 确认后 → 允许进入真实执行（P8.3） | preview 绕过 contract/approval |

### 非目标

- ❌ 不实现真实执行 / 不连真实系统

## 5.2 Simulation Schema

```text
ExecutionPreview {
  preview_id       string
  contract_id      string   // 关联 P8.1
  target           object   // {namespace, resource_type, resource_id}
  impact           string   // 影响范围（如 1 pod）
  risk             enum     // low|medium|high
  rollback         enum     // available|not_available
  actions          []string // 预览动作列表
  status           enum     // pending|approved|rejected
  environment_snapshot object // 评审补充：执行前环境状态快照
  resource_version string   // 评审补充：目标资源版本（如 pod version=v1）
  expected_change  object   // 评审补充：预期变更（如 restartCount 3→4）
  rollback_plan    object   // 评审补充：明确回滚计划
}
```

### 评审补充：Preview 状态快照（具备审计价值）

Preview 不只是文字说明，必须保存可审计状态：

```text
restart pod nginx → Preview 记录:
  environment_snapshot: {namespace: a, deployment: nginx}
  resource_version:     pod version=v1, restartCount=3
  expected_change:      restartCount 3→4（single pod restart）
  rollback_plan:        available（无需人工，重启无状态）
```

`environment_snapshot` / `resource_version` / `expected_change` / `rollback_plan` 缺一 → Preview 不具备审计价值，拒绝 approved。

### Rollback 责任边界（评审缺口 2 补齐）

| 组件 | 责任 |
|------|------|
| Agent | 提出 rollback 建议 |
| Human | 批准 rollback |
| Policy Engine | 检查 rollback（是否允许/是否超限） |
| Adapter | 执行 rollback（按 contract.rollback_policy） |

**禁止：Agent 自动 rollback**（rollback 也是执行动作，必须经 Human 批准 + contract）。

### 接口

```text
generate_preview(contract: ExecutionContract) -> ExecutionPreview
approve_preview(preview_id) -> ExecutionPreview   // 人工确认，状态 → approved
```

### 关键约束

- preview 生成**不触发任何真实副作用**。
- 只有 `approved` 的 preview 才允许 adapter 真实执行（P8.3）。
- impact/risk/rollback 必须显式评估，人工确认后才能继续。
- 未确认（pending/rejected）→ 不进入真实执行。

## 5.3 Security Boundary

- **无副作用**：preview 是纯只读模拟，不产生执行副作用。
- **人工确认门**：preview approved 前，contract 不进入真实执行。
- 与 P8.1 dry-run / P8.3 Adapter.dry_run 协同：dry_run 返回 preview 语义，approved 后才真实执行。

## 5.4 Test Plan（T1-T6）

- T1 生成 preview 无副作用
- T2 impact/risk/rollback 显式评估
- T3 preview 未确认 → 不真实执行
- T4 approved → 允许 adapter 执行
- T5 preview 绑定 contract（无 contract 不生成）
- T6 **状态快照**（评审补充）：缺 environment_snapshot/resource_version/expected_change/rollback_plan → 拒绝 approved；Agent 不能自动 rollback（rollback 必须 Human 批准 + contract）
